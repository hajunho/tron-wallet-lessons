# 발표 슬라이드 50장 대본 (gamma.app "텍스트 붙여넣기"용)

대상: 혼합 청중(중고등학생 + 일반인). 초등 이야기 장은 청중 전체의 이해를 돕는 비유 도입으로 씁니다.
사실 출처: 이 저장소의 13개 레슨(각 레슨의 `expected-output.txt`)과, 집필자에게 별도로 전달되는 검증 사실 목록입니다(그 목록은 저장소에 포함되지 않습니다). 모든 숫자는 연습 나라(테스트넷) 기준입니다.

## 6. 레슨 01. 12개 단어로 만든 비밀 열쇠

규칙 1: 열쇠(12단어)는 나만 안다. 고객센터도 모른다.
아무도 못 맞히는 무작위 128비트에서 12단어가 나오고, 12단어에서 개인키가 나옵니다.
같은 12단어를 넣으면 언제 어디서나 같은 열쇠가 다시 깎입니다.
그래서 12단어를 아는 사람은 곧 주인입니다. 재설정 버튼은 없습니다.

## 7. 이야기: 주사위 열두 번

토리가 보물상자 열쇠를 자꾸 잃어버려요. 노드 아저씨가 주사위를 굴려 12단어 주문을 만들어 줘요.
주문을 아는 사람은 누구든 똑같은 열쇠를 깎을 수 있어요. 그래서 아저씨도 주문을 묻지 않아요.
장부지기(노드)도 주문을 몰라야 해요. 잃어버리면 다시 만들어 줄 사람이 없어요.
"열쇠(12단어)는 나만 안다. 고객센터도 모른다."

## 9. 레슨 02. 열쇠에서 우편함 번호가 나와요

규칙 2: 주소는 모두에게, 열쇠는 아무에게도.
개인키 → 공개키 → keccak256 → 뒤 20바이트 → 앞에 `41` → base58check → T로 시작하는 34글자.
한쪽 방향뿐입니다. 주소에서 열쇠로 돌아가는 길은 없습니다.
그래서 주소는 친구·거래소·가게에 마음껏 알려 줘도 됩니다.

## 10. 실습: 주소 만들기와 엑스레이

같은 12단어에서 여러 개의 주소가 나오는 것(index 0, 1, 2…)을 직접 봅니다.
놀이터에서 T주소 ↔ `41`hex ↔ `0x` 를 눌러 보며 세 표기가 같은 20바이트임을 확인합니다.
놀이터: `playground/address-xray.html`, `playground/dice-to-words.html`

```bash

```

## 11. 원리: 앞뒤 네 글자만 보면 안 되는 이유

주소는 base58check라 한 글자 오타는 앱이 잡아 줍니다. 하지만 "닮은 주소"는 못 잡습니다.
앞 몇 글자가 같은 주소는 컴퓨터가 얼마든지 만들 수 있고, 체크섬도 멀쩡합니다.
거래 내역에 닮은 주소를 끼워 넣는 수법이 여기서 나옵니다(주소 오염).
비교는 앞뒤가 아니라 전체, 입력은 손이 아니라 QR·주소록.

## 12. 안전 카드: 공개된 니모닉은 이미 남의 것

이 저장소의 데모 주소 `TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH` 는 잔고가 있는데도 전송을 못 합니다.
`owner_permission` 의 키가 계정 자신이 아니라 `41156f4463ce90ac11e1855ff99e4273806ad847cf` 로 바뀌어 있습니다.
누군가 권한을 먼저 자기 키로 바꿔 둔 것입니다. 조회·서명·리허설은 되지만 전송은 영원히 불가능합니다.
새어 나간 12단어를 "조심해서 쓰는" 방법은 없습니다.

## 14. 레슨 03. 광장에 걸린 장부: 1 TRX는 사탕 100만 알

규칙 3: 잔고는 앱이 아니라 장부(탐색기)에서 확인하고, 토큰은 이름이 아니라 컨트랙트 주소로 알아본다.
1 TRX = 1,000,000 sun. 화면의 소수점은 사람 편의고, 체인은 정수 sun만 셉니다.
TRX 잔고와 TRC-20(USDT) 잔고는 **다른 장부**에 적힙니다.
한 번도 TRX를 받은 적 없는 계정은 조회하면 빈 객체 `{}` 가 돌아옵니다. 아직 활성화 전입니다.

## 15. 실습: 체인에서 직접 읽기

같은 주소를 앱 없이 노드에 물어봅니다. TRX는 sun 정수로, USDT는 decimals 6으로 나옵니다.
Nile USDT 컨트랙트는 `TXYZopYRdj2D9XRtbG411XZZ3kM5VkAeBf` 하나뿐입니다. 이름이 아니라 이 주소가 신분증입니다.
탐색기와 숫자를 대조하는 것까지가 한 세트입니다: `https://nile.tronscan.org`

```bash
npm run l03
```

## 17. 레슨 04. 연료: 대역폭 입장권과 에너지 입장권

규칙 4: USDT만 있고 TRX가 0이면 아무것도 못 보낸다. 연료(입장권)가 먼저다.
대역폭은 봉투의 바이트 수만큼 씁니다. 계정마다 **하루 600 무료**.
에너지는 스마트컨트랙트 실행에 쓰고 **무료가 없습니다**. USDT 전송이 여기에 해당합니다.
부족하면 TRX를 그 자리에서 태워 메웁니다. 그래서 TRX 0은 곧 정지 상태입니다.

## 18. 숫자로 보는 연료

대역폭 가격 1,000 sun/byte, 에너지 가격 100 sun/energy (체인 파라미터로 확인).
단순 TRX 전송은 약 266바이트 → 무료 대역폭이 없으면 0.266 TRX 소각.
USDT 전송 에너지는 어느 API로 재느냐에 따라 다릅니다: 리허설 `energy_used` 14,650, `estimateEnergy` 21,975(받는 쪽이 USDT 보유), 37,063(받는 쪽 USDT 0) → 약 1.5~3.7 TRX 소각.
에너지 가격은 이력이 있습니다: 420 → 210 → 100 sun. 지금 숫자를 외우지 말고 조회하세요.

## 19. 실습: 입장권 게이지 읽기

사용량이 0이면 응답에서 필드가 아예 빠집니다. 그래서 코드는 `?? 0` 으로 받습니다.
놀이터에서 봉투 크기와 에너지를 넣어 소각될 TRX를 계산해 봅니다: `playground/ticket-board.html`

npm run l04

## 20. 레슨 05. 편지 쓰고 도장 찍기(아직 안 보내요)

규칙 5: 도장을 찍기 전에 봉투(트랜잭션 내용)를 끝까지 읽는다.
봉투에는 받는 주소, 금액(sun), 참조 블록, 유효기간이 들어갑니다.
트론에는 nonce가 없습니다. 대신 최근 블록 참조와 **만료 60초**로 중복을 막습니다.
그래서 재촉은 통하지 않습니다. 만료되면 아무 일도 없었던 것이 되고, 새로 만들면 됩니다.

## 21. 원리: 봉투 번호는 도장 전에 정해진다

`txID = sha256(raw_data_hex)`. 서명하기 전에 이미 번호가 확정됩니다.
내용이 한 글자만 달라도 완전히 다른 번호가 됩니다. 그래서 도장은 "이 내용 그대로"에 찍는 것입니다.
메모를 붙이면 내용이 바뀌므로 번호도 바뀝니다. 메모는 **서명 전에** 붙여야 하고, 수수료 1 TRX가 듭니다.
만료를 연장하면 새 객체를 써야 합니다. 원본을 그대로 서명하면 내용과 번호가 어긋나 거부됩니다.

## 22. 실습: 봉투 한 칸씩 읽기

서명 한 개는 130자리 hex입니다. 다른 키로 서명하려 하면 노드에 가기도 전에 거부됩니다.
`Private key does not match address in transaction` 이 그 문구입니다.

```bash

```

## 23. 레슨 06. 진짜로 보내기(연습 나라에서)

규칙 6: 보내면 되돌릴 수 없다. 처음 보내는 곳은 소액 먼저.
브로드캐스트는 우체통에 넣는 것입니다. 꺼낼 수 없습니다. 노드도, 고객센터도 못 꺼냅니다.
약 3초마다 새 블록이 붙고, 조금 뒤 확정 블록이 따로 생깁니다. "들어왔다"와 "확정됐다"는 다릅니다.
그래서 처음 보내는 주소에는 아주 적은 금액을 먼저 보내고 도착을 확인합니다.

## 24. 실습: 기본은 미리보기

이 레슨만 `MNEMONIC` 이 필요합니다(전송 주체가 있어야 하니까). 없으면 안내하고 종료합니다.

수신자는 같은 12단어의 두 번째 주소입니다. 자기 자신에게 보내면 트론이 거부합니다.

## 25. 레슨 07. 영수증과 발자국

규칙 7: "보냈다"는 말 대신 txID로 영수증을 본다.
영수증(receipt)에는 블록 번호, 수수료, 결과가 적힙니다. 단순 전송이면 `net_fee`, 컨트랙트면 `energy_fee` + `net_fee`.
방금 넣은 봉투의 영수증은 빈 객체 `{}` 일 수 있습니다. 아직 굳지 않은 것이지 실패가 아닙니다.
컨트랙트를 쓴 봉투에는 발자국(이벤트 로그)이 남습니다. Transfer 토픽은 EVM과 같은 값입니다.

## 26. 실습: 영수증 세 칸 읽기

txID를 주면 그 영수증을, 없으면 최근 블록에서 하나를 자동으로 골라 읽습니다.
확인할 세 칸: 결과가 SUCCESS인지, 발자국의 받는 주소가 내 주소인지, 토큰 주소가 진짜인지.
캡처는 꾸밀 수 있고 실패한 거래도 txID와 수수료가 있습니다. 그래서 캡처가 아니라 txID를 받습니다.

```bash
npm run l07
```

## 28. 레슨 08. '나야'라고 증명하기(돈은 안 들어요)

규칙 8: 무엇에 도장 찍는지 읽지 못하면 찍지 않는다.
메시지 서명은 체인에 올라가지 않습니다. 수수료 0, 블록도 안 씁니다.
서명 한 장으로 "누가 무엇을 허락했다"가 성립할 수 있습니다. 그게 위험의 정체입니다.
읽을 수 없는 hex 덩어리에 도장을 찍으라는 요청은 예외 없이 거절합니다.

## 29. 원리: 같은 열쇠, 다른 프리픽스, 다른 주소

트론은 `"\x19TRON Signed Message:\n"` 을 붙여 해시합니다. 이더리움은 `"\x19Ethereum Signed Message:\n"` 입니다.
같은 서명을 이더리움 프리픽스로 복원하면 전혀 다른 주소가 나옵니다. 그래서 서명은 나라를 건너 재사용되지 않습니다.
구조화 서명 TIP-712는 EIP-712와 계산이 같습니다. T주소에서 `41` 을 떼면 그대로 EVM 주소입니다.
검증은 "복원된 주소 == 기대한 주소" 비교로만 합니다. 함수가 false를 돌려주지 않고 예외를 던지기도 합니다.

## 30. 실습: 팝업을 판별하는 눈

서명하고, 복원하고, 프리픽스를 바꿔 다른 주소가 나오는 것까지 한 번에 봅니다. 네트워크 없이 돌아갑니다.
놀이터에서 진짜 같은 팝업과 위험한 팝업을 골라 봅니다: `playground/signing-popup-simulator.html`
읽을 세 칸은 언제나 같습니다. 누구에게(spender), 얼마(value), 언제까지(deadline).

```bash
npm run l08
```

## 31. 이야기: 빈 종이에 도장 찍으라는 여우 씨

비티가 말해요. "네가 진짜 토리인지 증명해 봐." 토리가 종이에 이름을 쓰고 도장을 찍어요. 우표는 안 들어요.
그때 여우 씨가 아무것도 안 적힌 종이를 내밀어요. "여기도 그냥 찍어 줘. 뭐라고 써 있는지는 몰라도 돼."
토리가 고개를 저어요. "읽을 수 없으면 안 찍어요." 여우 씨가 슬그머니 물러가요.
"무엇에 도장 찍는지 읽지 못하면 찍지 않는다."

## 32. 레슨 09. 사탕통 장부와 허락증(TRC-20)

규칙 9: 허락(approve)은 필요한 만큼만, 다 쓰면 0으로.
`approve(spender, amount)` 는 "이 주소가 내 토큰을 이만큼까지 꺼내 가도 된다"는 허락증입니다.
남은 한도는 `allowance(owner, spender)` 로 언제든 조회됩니다. 취소는 삭제가 아니라 **0으로 다시 쓰기**입니다.
토큰을 받는 데는 승인이 필요 없습니다. 승인은 항상 "꺼내 가도 됨" 쪽입니다.

## 33. 실습: 허락증 해독하기

함수 선택자는 EVM과 같습니다. `transfer` = `a9059cbb`, `approve` = `095ea7b3`.
팝업의 긴 hex를 직접 잘라 "어느 토큰, 누구에게, 얼마까지"를 읽어 냅니다.
놀이터: `playground/approve-decoder.html` — calldata를 붙여 넣으면 세 칸으로 풀어 줍니다.

```bash
npm run l09
```

## 34. 레슨 10. 리허설: 보내기 전에 미리 해보기

규칙 10: 앱이 "실패할 것 같다"고 하면 보내지 않는다.
노드에 "이거 되나요?"를 먼저 물어볼 수 있습니다. 공짜이고, 체인에 아무것도 남지 않습니다.
성공하면 필요한 에너지가 숫자로 나옵니다. 실패하면 `REVERT opcode executed` 가 나옵니다.
실패한 거래도 수수료는 나갑니다. 리허설에서 넘어진 봉투는 보내지 않는 것이 이득입니다.

## 35. 실습: 보내기 전 점검표

정상 금액은 통과하고, 잔고를 넘는 금액은 리허설에서 넘어집니다. 두 경우를 나란히 봅니다.
점검표: 네트워크 / 받는 주소 전체 / 금액과 단위 / TRX 잔고 / 리허설 결과 / 최대 수수료 / 소액 먼저.
앱의 빨간 경고는 사기가 아니라 방패입니다. 무시하라고 하는 쪽이 이득을 봅니다.

```bash
npm run l10
```

## 36. 파트 4. 옆 나라·실패·점검

같은 열쇠가 여러 나라를 엽니다. 그래서 나라 이름을 글자까지 맞춰야 합니다.

## 37. 레슨 11. 한 열쇠, 두 나라, 두 경로: BTTC에서도 열려요

규칙 11: 보내기 전에 나라(네트워크)를 상대와 글자까지 맞춘다.
BTTC는 EVM 호환입니다. 같은 개인키를 `ethers.Wallet` 에 넣으면 T주소의 20바이트와 같은 `0x` 주소가 나옵니다.
경로가 둘이라는 점이 함정입니다. 트론 경로는 `m/44'/195'/…`, 이더리움 경로는 `m/44'/60'/…` 이고 키가 다릅니다.
`0x` 주소는 여러 EVM 나라에서 모양이 같습니다. "주소가 맞으니 됐다"가 통하지 않는 이유입니다.

## 38. 세 체인 비교: 트론 · BTTC · 이더리움

| 항목 | 트론 | BTTC | 이더리움 |
|---|---|---|---|
| 주소 | `T…` 34글자 base58check | `0x…` 20바이트 | `0x…` 20바이트 |
| 기본 파생 경로 | `m/44'/195'/0'/0/0` | `m/44'/60'/…`(EVM 관행) | `m/44'/60'/…` |
| 수수료 | 대역폭(하루 600 무료) + 에너지 | gas × gasPrice (레거시) | gas 기반, EIP-1559 |
| 중복 방지 | nonce 없음. 참조 블록 + 만료 60초 | nonce | nonce |
| 체인 ID | Nile 3448148188 / 메인넷 728126428 | Donau 1029 / 메인넷 199 | (확인 필요) |
| 구조화 서명 | TIP-712 = EIP-712 (계산 동일) | EIP-712 | EIP-712 |

## 39. 실습: 두 나라 우편함 열어 보기

같은 열쇠로 T주소와 `0x` 주소를 만들고, Nile과 Donau에서 잔고를 각각 읽습니다.
데모 니모닉의 이더리움 경로 주소에는 Donau BTT가 조금 있고, 트론 경로 주소에는 0입니다. 경로가 다르면 지갑이 다릅니다.
Donau 가스는 레거시입니다. EIP-1559 필드를 넣으면 실패할 수 있습니다(확인 필요).

```bash
npm run l11
```

## 40. 이야기: 비티의 비밀이 풀리는 날

레슨 2에서 비티가 말했어요. "토리! 네 우편함 번호 안에 우리 나라 번호가 숨어 있어!"
오늘 그 비밀이 풀려요. T 번호에서 앞 글자를 떼어 내면 옆 나라 번호가 나와요. 열쇠 하나로 두 우편함이 열려요.
그런데 우표 규칙이 달라요. 비티가 말해요. "봉투에 나라 이름 썼어? 글자까지 똑같이!"
"보내기 전에 나라(네트워크)를 상대와 글자까지 맞춘다."

## 41. 레슨 12. 실패 탐정: 왜 안 됐을까?

규칙 12: 실패는 단서다. "고쳐 준다"는 사람은 사기다.
일부러 아홉 가지 실패를 일으켜 반송 도장을 읽습니다. 자산은 한 번도 움직이지 않습니다.
실패는 두 종류입니다. 내 컴퓨터가 먼저 막는 것과, 노드가 거부하는 것.
대부분의 실패에서는 장부에 아무것도 오르지 않으니 잔고가 그대로입니다.

## 42. 실습: 에러 문구가 곧 원인

`account [T…] does not exist` — 받는 계정이 아직 활성화되지 않았습니다. 활성화는 그 주소가 TRX를 **받으면** 됩니다.
`Cannot transfer TRX to the same account` — 자기 자신에게는 못 보냅니다.
`REVERT opcode executed` — 컨트랙트가 거절했습니다. 보통 토큰 잔고 부족입니다.
문구를 지우지 말고 캡처하세요. 문구를 읽어 주는 사람은 정상, 열쇠를 달라는 사람은 사기입니다.

```bash
npm run l12
```

## 43. 레슨 13. 내 지갑 점검과 졸업

규칙 13: 한 달에 한 번 점검, 사고가 나면 순서대로, 혼자 끙끙대지 않기.
점검 네 칸: 잔고, 계정 권한, 남은 허락증, 최근 거래.
권한 점검이 핵심입니다. `owner_permission` 의 키가 내 계정 주소와 같아야 정상입니다.
내가 보낸 기억이 없는 거래가 하나라도 있으면, 그 지갑은 이미 내 것이 아닙니다.

## 44. 실습: 한 달 점검과 사고 대응 순서

한 명령으로 네 칸을 한 번에 찍습니다. 주소만 있으면 누구나 할 수 있는 점검입니다.
사고 대응 순서: ① 멈추기 → ② 새 지갑 만들기 → ③ 자산 옮기기(소액 먼저) → ④ 허락 0으로 → ⑤ 알리기·신고.
"복구 구문을 입력하면 진단해 드립니다"라는 점검은 없습니다. 점검은 주소만으로 합니다.

```bash
npm run l13
npm run audit
```

## 45. 13개 안전 규칙 한 장

1. 열쇠(12단어)는 나만 안다. 고객센터도 모른다.
2. 주소는 모두에게, 열쇠는 아무에게도.
3. 잔고는 앱이 아니라 장부(탐색기)에서 확인하고, 토큰은 이름이 아니라 컨트랙트 주소로 알아본다.
4. USDT만 있고 TRX가 0이면 아무것도 못 보낸다. 연료(입장권)가 먼저다.
5. 도장을 찍기 전에 봉투(트랜잭션 내용)를 끝까지 읽는다.
6. 보내면 되돌릴 수 없다. 처음 보내는 곳은 소액 먼저.
7. "보냈다"는 말 대신 txID로 영수증을 본다.
8. 무엇에 도장 찍는지 읽지 못하면 찍지 않는다.
9. 허락(approve)은 필요한 만큼만, 다 쓰면 0으로.
10. 앱이 "실패할 것 같다"고 하면 보내지 않는다.
11. 보내기 전에 나라(네트워크)를 상대와 글자까지 맞춘다.
12. 실패는 단서다. "고쳐 준다"는 사람은 사기다.
13. 한 달에 한 번 점검, 사고가 나면 순서대로, 혼자 끙끙대지 않기.

## 48. 이 자료가 틀리지 않게 유지하는 방법
