## 왜 만들었나

출발점은 [soaryong/wallet-practice](https://github.com/soaryong/wallet-practice)입니다. 이더리움, Sui, Solana를 다루는 12개 레슨짜리 개발자용 실습 저장소입니다. 흐름이 좋았습니다. 키 만들기 → 읽기 → 쓰기 → 다른 체인에서도 같은 키 → 서명과 권한 → 보내기 전 시뮬레이션 → 보낸 후 검증 → 실패 케이스.

이것을 두 방향으로 늘렸습니다.

1. **체인을 트론과 BTTC로.** 트론에는 이더리움에 없는 개념이 있습니다. 대역폭과 에너지(gas 대신), nonce 없는 트랜잭션, 계정 활성화 수수료, 계정 권한. 이 개념들이 오히려 "지갑이 왜 이렇게 생겼나"를 더 잘 보여줍니다.
2. **대상을 네 갈래로.** 원본은 개발자용입니다. 초등학생, 중·고등학생, 대학생·개발자, 일반인이 같은 레슨을 각자의 깊이로 읽게 만들었습니다.

같은 날 원본 저장소에는 별도로 [PR](https://github.com/soaryong/wallet-practice/pull/2)을 보냈습니다. Sui 공개 풀노드가 JSON-RPC를 폐기해서 Lesson 5가 아예 실행되지 않는 문제를 gRPC로 고친 것입니다.

## 순서

### 1. 사실 확인부터 (약 2시간)

코드를 한 줄도 쓰기 전에 tronweb 6.5.0과 ethers 6.17.0으로 Nile·Donau 테스트넷을 직접 두드렸습니다. 결과가 [verified-facts.md](verified-facts.md)입니다.

이 단계를 먼저 한 이유는, 블록체인 라이브러리 문서가 실제 동작과 다른 경우가 많기 때문입니다. 실제로 어긋난 것들이 나왔습니다.

- `TronWeb.utils`는 정적 속성이 아닙니다. `const { utils } = require('tronweb')`로 받아야 합니다.
- `trx.sign(tx, pk)`는 입력 객체를 제자리에서 바꿉니다. 원본을 보관하려면 미리 복사해야 합니다.
- `extendExpiration`은 입력의 `raw_data`만 바꾸고 `txID` 문자열은 갱신하지 않습니다. 그 객체로 서명하면 `Invalid transaction`이 납니다.
- `verifyTypedData`는 불일치 시 `false`가 아니라 예외를 던집니다.
- `verifyMessageV2`는 다른 메시지를 넣어도 예외 없이 **다른 주소**를 돌려줍니다. 검증은 "복원된 주소 == 기대 주소" 비교로 해야 합니다.
- 노드가 돌려주는 `message`는 hex입니다. `Buffer.from(message, 'hex').toString()`으로 풀어야 사람이 읽습니다.
- `sendTrx(to, amount, from)`에서 `to === from`이면 예외입니다. 그래서 모든 레슨의 기본 수신자는 같은 니모닉의 index 1 주소입니다.

에러 형태는 잔고 0의 일회용 지갑으로 실제 브로드캐스트까지 해서 확인했습니다. 자산이 움직일 수 없으니 안전하고, 덕분에 레슨 12의 에러 사례가 전부 실제 노드 응답입니다.

**우연한 발견.** 공개된 데모 니모닉(`abandon ×11 about`)의 Nile 주소는 잔고가 있는데도 `owner_permission`의 키가 계정 자신이 아닌 다른 키로 바뀌어 있었습니다. 누군가 권한을 가져간 것입니다. "니모닉이 새면 권한까지 빼앗긴다"는 안전 레슨의 실제 사례가 되어서, 레슨 3과 13에서 이 주소를 직접 조회하게 만들었습니다.

### 2. 커리큘럼 설계 (3안 → 심사 → 통합)

세 가지 관점으로 커리큘럼을 각각 설계했습니다.

- **교육학 우선**: 초등학생이 이해하고 즐길 수 있는 비유와 활동을 최우선으로
- **개발자 우선**: 원본의 검증된 12레슨 흐름을 트론으로 정확히 옮기는 것을 최우선으로
- **안전 우선**: 일반인이 사기와 실수로 자산을 잃지 않게 만드는 것을 최우선으로

두 명의 심사자가 서로 다른 렌즈(교실에서 진행 가능한가 / 기술적으로 정확한가)로 채점했고, 최고안을 뼈대로 나머지 안의 장점을 이식해 최종 13레슨을 만들었습니다.

**순서를 셋 바꿨습니다.**

- **자원 모델(4)을 쓰기(5~6) 앞으로.** 첫 전송에서 활성화 수수료와 대역폭 소모가 바로 나타납니다. 예측하고(4) 실행하고(6) 영수증으로 검산하는(7) 고리를 만들려면 자원이 먼저여야 합니다.
- **영수증(7)을 전송(6) 바로 뒤로.** 트론은 3초 블록, 60초 만료입니다. "보냈다 → 확인했다"를 한 차시에 묶어야 기억이 이어집니다.
- **BTTC(11)를 뒤로.** 레슨 2에서 "T주소 속에 옆 나라 주소가 숨어 있다"고 씨앗을 심고, 트론의 자원·서명·허락을 모두 배운 뒤 대조하면 효과가 큽니다.

### 3. 집필

레슨마다 집필 → 검수 → 수정을 파이프라인으로 돌렸습니다. 놀이터 6개는 병렬로 작성했습니다.

집필자에게 준 규칙 중 중요한 것들입니다.

- 사실은 [verified-facts.md](verified-facts.md)에 있는 것만. 없으면 `(확인 필요)` 표시.
- `expected-output.txt`는 **반드시 실제 실행으로 생성**. 문서의 출력 예시는 그 파일에서 복사.
- 누구도 `SEND_TX=true`로 실행하지 않는다. `.env`를 만들지 않는다.
- 초등 이야기는 8~12문장, 한 문장 20자 내외. 새 숫자를 만들지 않는다.

### 4. 검수

레슨 01~10에서 87건, 11~13에서 42건, 저장소 전체 일관성에서 79건이 나왔습니다. 합계 208건을 모두 수정했습니다.

검수자들은 문서를 읽는 데 그치지 않고 **직접 실험을 돌려** 틀린 것을 잡았습니다. 그 과정에서 새 사실이 나와 [verified-facts.md](verified-facts.md)의 "4차 확인" 절이 추가됐습니다.

실제로 틀렸던 것들입니다.

| 문서에 있던 주장 | 실제 |
|------------------|------|
| feeLimit에 TRX 단위 소수를 넣으면 "에너지 부족"으로 실패 | tronweb이 빌드 단계에서 `Invalid feeLimit provided` 예외. 노드까지 가지 않음 |
| T주소 앞 3글자를 맞추려면 58² ≈ 3,364번 | 두 번째 글자는 25종만 나오므로 약 25×58 ≈ 1,450번 (무작위 키 2만 개로 확인) |
| 니모닉 마지막 단어를 다음 단어로 바꾸면 1/16 확률로 우연히 통과 | 약 1/256. "아무 단어로" 바꿨을 때가 1/16 |
| 특정 주소로 실행하면 "에너지 부족" 분기가 나온다 | 그 주소의 EnergyLimit이 39,528로 충분해서 여전히 "충분"이 나옴 |
| receipt의 `net_usage`는 266이었다 | 관찰된 것은 `net_fee: 266000`. `net_usage`는 미확인 |
| keccak256이 32바이트 입력을 뒤섞는다 | 입력은 비압축 공개키 64바이트 |
| 놀이터 6개 모두 인터넷 없이 열린다 | 3개는 CDN에서 ethers를 받음 |

**분량 비율 문제.** 거의 모든 레슨에서 개발자 블록이 목표 30%의 1.5~2배(47~56%)로 커져 초등·활동 블록을 절반으로 눌렀습니다. 코드 블록의 출력 인용을 핵심 줄만 남기고 활동 블록을 보강해 28~38%로 내렸습니다.

**해결하지 못한 구조적 충돌 하나.** 스타일 가이드는 초등 이야기 블록을 전체의 15%로 정했지만, 동시에 "8~12문장, 한 문장 20자 내외"로 못 박았습니다. 12문장이면 약 300~400자인데, README가 250~400줄이면 15%가 될 수 없습니다. 모든 집필자가 이 지점에서 멈췄고, 전원이 문장 수 규정을 택했습니다. 이야기는 짧게 치고 빠지는 도입부라는 판단입니다. 비율 목표가 틀렸던 것이고, 다음에 고칠 때는 초등 블록 목표를 5~8%로 낮추는 것이 맞습니다.

### 5. 검증과 공개

새 위치에 클론해서 `npm install` 후 `npm test`를 돌려 13/13을 확인하고 공개했습니다. 놀이터는 로컬 HTTP 서버에 올려 브라우저에서 직접 조작해, 검증된 값이 나오는지 확인했습니다.

- 주사위 놀이터: 엔트로피 0 → `abandon ×11 about` → 개인키 `b5a4ce…9a28` → `0xC8599111F29c1e1E061265b4AF93eA1F274aD78A` → `TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH`. 수동 계산한 base58check가 ethers 결과와 일치.
- 승인 해독기: 무제한 approve calldata를 넣으면 `2^256−1` 경고와 spender의 T주소·0x주소를 정확히 표시.

## 안전 설계

자료가 사람에게 손해를 입히지 않는 것이 가장 중요한 제약이었습니다.

1. **테스트넷만.** `lib/guard.js`가 메인넷 host를 차단 목록으로 막습니다.
2. **기본은 미리보기.** `SEND_TX=true`를 명령 앞에 직접 붙였을 때만 전송이 일어납니다. `.env`에 박아 두지 말라고 여러 곳에 적었습니다.
3. **데모 니모닉으로는 전송 불가.** guard가 막습니다. 그리고 실제로 그 주소의 권한이 남에게 있어서 어차피 노드가 거부합니다.
4. **무제한 approve 차단.** guard가 `2^256−1`에 가까운 금액을 막습니다.
5. **비밀값 마스킹.** `lib/print.js`가 기본으로 가리고 `SHOW_SECRETS=true`일 때만 보여 줍니다.
6. **브로드캐스트 직전 단일 관문.** 전송하는 레슨 3개(06, 09, 11)가 모두 `assertCanSend`를 거칩니다. 레슨 12의 유일한 실제 브로드캐스트는 잔고 0의 일회용 지갑입니다.
7. **시세·투자 금지.** 어떤 대상 블록에도 쓰지 않습니다. 교사 가이드에는 학생이 물어볼 때의 대응 스크립트를 넣었습니다.

### 켜야 하는 것

주간 재검증 워크플로가 `.github/workflows/`에 들어가지 못했습니다. 푸시에 쓴 토큰에 `workflow` 권한이 없었습니다. 파일은 [../ci/reverify.yml](../ci/reverify.yml)에 있고 켜는 방법은 [../ci/README.md](../ci/README.md)에 있습니다.

### 시간이 지나면 틀려지는 값

테스트넷이라 아래 값은 바뀝니다. `npm test`가 실패하면 여기부터 보세요.

- 데모 주소의 TRX·USDT 잔고 (faucet 사정에 따라 0이 될 수 있습니다)
- BTTC Donau의 gasPrice (기록 당시 9e15 wei, 단순 전송 ≈ 189 BTT)
- 에너지·대역폭 가격 (체인 파라미터로 조회하므로 스크립트는 자동 반영되지만 문서의 예시 숫자는 고정)
- Nile 테스트 USDT 컨트랙트 주소
- faucet URL

`npm run expected`로 `expected-output.txt` 전체를 다시 만든 뒤, 문서의 출력 인용을 맞추면 됩니다.

### 검증하지 못한 것

[verified-facts.md](verified-facts.md)에 `(확인 필요)`로 표시한 항목들입니다. 주요한 것은 이렇습니다.

- 무료 대역폭이 트랜잭션 바이트보다 적을 때 **부족분만 과금되는지 전체가 과금되는지**. 입장권 계산기는 "부족분만" 모델을 쓰고 화면에 그 한계를 적어 두었습니다.
- 에너지 **위임(delegate) 실행**. 조회 API만 확인했습니다.
- `frozenV2`의 `type` 없는 첫 항목을 대역폭으로 해석하는 것. 관례입니다.
- 스테이킹 언스테이크 대기 기간.
- 지갑 앱의 구체적 화면. 앱 버전마다 달라서 일반적인 설명만 했습니다.

### 구조적으로 고칠 것

- 초등 블록 분량 목표 15%는 문장 수 규정과 충돌합니다. 5~8%로 낮추는 것이 맞습니다.
- 레슨 7의 개발자 블록이 38%로 가장 큽니다. 영수증 필드가 많아서인데, 표로 접으면 더 줄일 수 있습니다.
- 놀이터에 종합 퀴즈 페이지가 없습니다. 처음 설계에는 있었지만 각 레슨의 `quiz.md`와 겹쳐서 넣지 않았습니다. 만든다면 `quizzes/*.json`을 놀이터와 터미널이 공유하는 구조가 좋습니다.

## 다른 체인으로 옮기려면

이 자료의 뼈대는 체인과 무관합니다. 옮길 때 순서는 이렇습니다.

1. **사실 확인을 먼저.** 그 체인의 SDK로 직접 두드려 [verified-facts.md](verified-facts.md) 같은 문서를 만드세요. 이 단계를 건너뛰면 문서가 조용히 틀립니다.
2. **비유는 그대로 쓸 수 있습니다.** 12단어 주문, 우편함 번호, 광장의 장부, 봉투와 도장, 영수증, 허락증은 어느 체인에서도 통합니다. 입장권(자원)만 트론 고유입니다. gas인 체인이면 "우표 값"으로 바꾸면 됩니다.
3. **13규칙은 거의 그대로.** 규칙 4(연료)와 11(네트워크)만 체인에 맞게 고치면 됩니다.
4. **`lib/`를 먼저 쓰세요.** 레슨 스크립트는 공용 모듈에 얇게 올라가 있습니다. `wallet`·`tron`·`guard`·`print`에 해당하는 것을 만들면 레슨은 빠르게 따라옵니다.
5. **검수에 실험을 요구하세요.** 이번에 잡힌 진짜 오류는 전부 검수자가 직접 실행해서 나왔습니다. 읽기만 하는 검수로는 안 나옵니다.
