## ✋ 손으로 해보기 <a id="hands"></a>

**활동: 주사위로 12단어 주문 카드 만들기** (교사용 상세 진행과 여우 씨 대사 카드는 [activity.md](./activity.md))

- 준비물: 주사위(저학년 2개, 고학년 4개), 한국어 단어표 100개([activity.md](./activity.md) 워크시트 A), 아래 주문 카드, 연필, 카드를 넣을 봉투.
- 시간: 25~30분. 이야기 5분 → 단어 고르기 10분 → 주문 읽어 보기 3분 → 놀이 7분 → 정리 5분.

**진행 요약**

1. **이야기 5분.** 위 "🧒 이야기로 시작"을 읽어 주고 "아저씨는 왜 주문을 안 물어봤을까?"를 던져 둡니다. 답은 마지막 발문에서 받습니다.
2. **단어 고르기 12번 (10분).** 카드의 1번 칸부터 12번 칸까지, 한 칸마다 주사위를 굴려 번호를 만들고 단어표에서 그 번호의 단어를 옮겨 적습니다. 같은 단어가 두 번 나와도 괜찮습니다(진짜 니모닉도 그렇습니다).
   - 저학년(주사위 2개): 번호 = 두 눈의 합 (2~12).
   - 고학년(주사위 4개): 번호 = (첫 눈 + 둘째 눈 + 셋째 눈 − 3) × 6 + 넷째 눈 (1~96). 예: 눈이 2, 5, 3, 4 → (2 + 5 + 3 − 3) × 6 + 4 = 46 → "강아지".
3. **주문 읽어 보기 (3분).** 각자 소리 내지 않고 자기 카드를 읽습니다. 옆 사람 카드는 보지 않습니다. "이 교실에 똑같은 카드가 두 장 있을 확률은?"을 물어봅니다.
4. **"주문 보여 주면 보물 뺏기기" 놀이 (7분).** 술래(여우 씨 역)가 "상자가 고장 났대, 주문만 보여 줘", "선생님이 확인하래"라고 **말로만** 속입니다. 카드를 보여 준 사람의 카드는 술래가 빈 카드에 그대로 베껴 갑니다. 술래는 빼앗거나 협박하지 않고, "아니요"를 들으면 물러납니다.
5. **정리 (5분).** 베낀 카드와 원래 카드를 나란히 놓고 "어느 쪽이 진짜?"를 묻습니다. 둘 다 진짜입니다. 주문을 아는 사람은 누구든 같은 열쇠를 깎을 수 있어서, 보여 주기만 해도 뺏긴 것과 같습니다.
6. 마지막에 카드를 접어 봉투에 넣고 자기만 아는 곳에 둡니다. 선생님도, 친구도 보지 않습니다.

## 🔍 원리 들여다보기 <a id="why"></a>

### 비유는 무엇을 가리킬까요?

| 비유 | 정식 용어 | 이 레슨에서 확인하는 값 |
|---|---|---|
| 주사위 굴리기 | 엔트로피(무작위 128비트) | `crypto.randomBytes(16)` 또는 `DICE` 주사위 눈 50개 이상 |
| 12단어 주문 | 니모닉(BIP-39 복구 구문) | 132비트 = 11비트 × 12, 마지막 단어에 체크섬 4비트 |
| 주문 외우기(섞기) | 시드(PBKDF2 2048회, 64바이트) | `mnemonicToSeedSync(mnemonic, passphrase)` |
| 열쇠 | 개인키(32바이트) | 경로 `m/44'/195'/0'/0/0`, 화면에는 마스킹 |
| 보물상자 | 지갑 | 열쇠에서 나온 T주소 하나 |

### 가짓수는 얼마나 클까요?

동전 1개를 던지면 앞/뒤 2가지, 10개면 2^10 = 1,024가지, 128개면 2^128가지입니다. 스크립트 `[1]` 단계가 이 수와 자릿수를 그대로 찍어 줍니다(위 워크시트 D 의 빈칸을 채워 보세요).

### 실험 1: 출력에서 한 줄 찾기

`npm run l01` 을 실행하고 `가짓수:` 로 시작하는 줄을 찾으세요. `2^128 = 340282366920938463463374607431768211456 ≈ 3.4×10^38 (39자리)` 가 보입니다. 이어서 `[3]` 단계의 `마지막 단어를 … 로 바꿈: false` 줄을 찾으세요. 12번째 단어 하나만 바꿔도 검증이 실패하는 이유는 마지막 단어 11비트 안에 체크섬 4비트가 들어 있기 때문입니다. 체크섬이 우연히 맞을 확률은 **아무 단어로** 바꿀 때 약 1/16 이지만, 스크립트처럼 **단어표의 바로 다음 단어로** 바꾸면 엔트로피 비트가 그대로일 때가 많아 거의 항상 `false` 입니다(약 1/256). 우연히 `true` 가 나오면 스크립트가 경고를 붙입니다.

### 실험 2: 환경변수 바꿔 보기

```
DICE="1,4,6,…" npm run l01                  # 눈 50개 이상, PASSPHRASE 없이
DICE="1,4,6,…" PASSPHRASE=토리 npm run l01   # 같은 DICE, PASSPHRASE 만 추가
```

두 실행의 `[4]` 단계 `시드(hex):` 줄과 `[5]` 단계 **마지막** 줄(`이번에 만든 … T주소 (PASSPHRASE 적용)`)을 비교하세요. 단어 12개는 그대로인데 시드와 이 T주소가 함께 달라집니다. `WORDLIST` 가 korean 이든 english 이든 마찬가지입니다. 단, `[5]` 위쪽 세 줄의 교차 검증 주소는 `(PASSPHRASE 없이)` 계산한 값이라 바뀌지 않습니다(`TronWeb.fromMnemonic` 과 ethers `fromPhrase` 는 passphrase 를 받지 않습니다). `DICE` 를 주지 않으면 실행마다 엔트로피가 새로 만들어져 비교할 수 없습니다.

### 왜 그렇게 설계했을까요?

128비트 숫자를 그냥 적어 두면 되는데, 왜 굳이 2048개 단어표에서 12단어를 고르게 했을까요? (힌트: `a1ff…0729` 같은 hex 32자리를 손으로 옮겨 적을 때와, 단어 12개를 옮겨 적을 때 어느 쪽이 오타를 알아채기 쉬운지, 그리고 체크섬 4비트가 하는 일을 생각해 보세요.)

### 비유의 한계 한 줄

주문은 외우는 것이지만 니모닉은 종이에 적어 두는 것입니다. 잃으면 아무도 다시 만들어 줄 수 없습니다.

### [1/6] 엔트로피 128비트

`가짓수:` 줄은 🔍 실험 1 에서 인용했습니다. `DICE` 를 주면 `sha256(눈 문자열)` 앞 16바이트를 씁니다(`makeEntropy`). 눈 하나가 log2(6) ≈ 2.585비트라 50개는 있어야 128비트를 넘깁니다.

### [2/6] 체크섬 + 11비트 조각 → 12단어

```
  sha256(엔트로피) 앞 4비트 = 체크섬: 1111
  전체 비트 수: 128 + 4 = 132비트 = 11비트 × 12
  번호 | 11비트      | 인덱스 | 단어
     1 | 11000011011 | 1563   | sell
```

2번 행까지 보이고 3~11번 행은 `****`, 12번 행에 마지막 단어가 나옵니다(`lib/print.js` 의 `maskMnemonic` 규칙). 스크립트는 비트를 직접 자른 뒤 `bip39.entropyToMnemonic` 과 비교합니다.

```js
const allBits = toBits(entropy) + toBits(sha256(entropy)).slice(0, 4); // 128 + 4 = 132비트
const chunk = allBits.slice(i * 11, (i + 1) * 11);                     // 11비트씩 12조각
rows.push({ index: parseInt(chunk, 2), word: wordlist[index] });       // 0~2047 → 단어
```

### [3/6] validateMnemonic

```
  마지막 단어를 "bulk"(단어표 다음 단어)로 바꿈: false
  1번째와 2번째 단어 순서를 바꿈: false
```

체크섬이 4비트뿐이라 **아무 단어로** 바꾸면 약 1/16 확률로 `true` 입니다(순서 바꾸기도 비슷). 스크립트가 쓰는 "바로 다음 단어"는 엔트로피 비트를 대체로 건드리지 않아 거의 항상 `false` 입니다(약 1/256).

### [4/6] 시드와 PASSPHRASE

```
  PASSPHRASE 를 "연습" 으로 바꾸면: ea39…5a5d (SHOW_SECRETS=true 로 전체 표시)
  두 시드가 같은가: false
```

`bip39.mnemonicToSeedSync(mnemonic, passphrase)` 입니다. PASSPHRASE 에는 체크섬이 없어 오타가 "틀렸다"가 아니라 "다른 지갑"이 됩니다.

> **표기 주의.** 이 레슨은 12단어 니모닉이므로 BIP-39 passphrase 는 **13번째 단어**입니다([GLOSSARY.md](../../GLOSSARY.md) "주문 자물쇠 하나 더" 항목과 같습니다). 흔히 쓰이는 "25번째 단어"라는 표현은 24단어 니모닉을 전제한 관용어라서 이 저장소에서는 쓰지 않습니다.

### [5/6] 시드 → 경로 → 열쇠 → T주소

```
    TronWeb.fromMnemonic (PASSPHRASE 없이): TAher5DKS6cdEWrxXfwZkioRGCg3R5dgMD
    lib.walletFromMnemonic (ethers, PASSPHRASE 없이): TAher5DKS6cdEWrxXfwZkioRGCg3R5dgMD
    bip32.fromSeed().derivePath (직접, PASSPHRASE 없이): TAher5DKS6cdEWrxXfwZkioRGCg3R5dgMD
  ⚠️  TronWeb.fromMnemonic 은 한국어 단어표를 읽지 못합니다: invalid mnemonic word at index 0
  영어 12단어와 한국어 12단어의 주소가 같은가 (같은 PASSPHRASE 로 비교): false
  이번에 만든 english 12단어의 T주소 (PASSPHRASE 적용): TAher5DKS6cdEWrxXfwZkioRGCg3R5dgMD
```

`TronWeb.fromMnemonic` 과 ethers `fromPhrase` 는 passphrase 인자가 없어, 교차 검증(다르면 예외)과 언어 비교는 같은 passphrase 조건끼리 합니다. 마지막 줄만 `[4]` 의 시드로 계산합니다.

```
  데모 주소: TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH (hex 41c8599111f29c1e1e061265b4af93ea1f274ad78a)
  ⚠️  이 주소는 전 세계가 아는 니모닉의 주소입니다. Nile 에서 실제로 owner/active 권한 키가 41156f4463ce90ac11e1855ff99e4273806ad847cf 로 바뀌어 있어, 개인키가 있어도 전송할 수 없습니다.
```

엔트로피가 전부 0이면 앞 11단어 인덱스가 0(`abandon`), 마지막 단어는 체크섬이 붙어 3(`about`)입니다. 권한 확인은 Lesson 03·13.

### 트론 vs EVM 차이

| 항목 | 트론 | EVM(이더리움·BTTC) |
|---|---|---|
| 12단어 만드는 법 | BIP-39, 동일 | BIP-39, 동일 |
| 시드 → 열쇠 경로 | `m/44'/195'/0'/0/0` (195) | `m/44'/60'/0'/0/0` (60) |
| 데모 니모닉의 주소 | `TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH` | 60' 키를 트론 주소로 바꾸면 `TPrkFhZ8LH8Mruco8vXyA496TaeFBrbmeU` |

`TronWeb.fromMnemonic` = `HDNodeWallet.fromPhrase(m, undefined, "m/44'/195'/0'/0/0")`. 경로가 다르면 같은 12단어도 주소가 달라집니다(Lesson 02·11).

### 함정 1개: 한국어 단어표는 NFKD

`bip39.wordlists.korean` 은 풀어쓰기(NFKD)라 `'가격'.length` 가 5입니다(실행으로 확인). 비교 전에 `normalize('NFC')`(스크립트의 `showWord`). ethers·tronweb 은 한국어 단어를 `invalid mnemonic word at index 0` 으로 거부합니다(실행으로 확인).

### 도전

- 쉬움: 눈 50개를 `DICE="…"` 로 두 번 실행해 `[5]` 마지막 줄이 같은지 보고, 눈 하나만 바꿔 주소가 통째로 바뀌는지 확인하세요.
- 어려움: `ENTROPY_BYTES` 32, `WORDS_PER_MNEMONIC` 24로 바꾸면 체크섬 8비트·264비트가 되어야 합니다(유도한 값이므로 실행해 확인 필요).

## 🏠 내 생활에서는 <a id="life"></a>

지갑 앱(TronLink 등)을 처음 설치하면 12개 단어를 보여 주며 "복구 구문을 적어 두세요"라고 안내합니다(정확한 화면 문구와 순서는 앱 버전마다 다릅니다. 확인 필요). 그 12단어가 이 레슨의 니모닉입니다. 앱을 지우고 다른 폰에 같은 12단어를 넣으면 같은 주소가 나옵니다. 앱이 지갑이 아니라 12단어가 지갑입니다.

이 화면은 **처음 한 번만** 보여 줍니다. 그 뒤로는 앱도, 만든 회사도, 고객센터도 이 단어를 다시 보여 주거나 물어볼 수 없습니다. 재설정 버튼도 없습니다. 그러니 그때 종이에 적어, 사진 찍지 말고, 인터넷에 올리지 말고, 집 안 두 곳에 나눠 보관하세요.

**이런 요청이 오면 사기인가?**

| 상황 | 사기? | 왜 |
|---|---|---|
| 고객센터 채팅이 "계정 확인을 위해 복구 구문 12단어를 입력하세요"라고 한다 | 예 | 고객센터는 12단어를 모르고, 알 필요도 없습니다. 묻는 순간 사기입니다. |
| 에어드랍(무료 코인) 페이지가 "지갑 연결"을 위해 복구 구문을 입력하라고 한다 | 예 | 정상적인 사이트는 12단어를 요구하지 않습니다. 입력하면 지갑이 통째로 넘어갑니다. |
| 앱을 처음 만들 때 백업 화면이 12단어를 보여 주고 적어 두라고 한다 | 아니오 | 정상입니다. 그때 한 번, 그 화면에서만 적으세요. |

**사기 유형 1개: 가짜 고객센터.** 지갑 앱 이름을 단 SNS 계정이나 채팅방이 "문제를 해결해 드리겠다"며 12단어를 묻습니다. 진짜 고객센터는 12단어를 물을 방법도, 물을 이유도 없습니다.

**앱에서 이 개념이 보이는 자리.** 설정 화면의 "복구 구문 백업", "지갑 추가/가져오기", 새 지갑을 만들 때의 "단어 순서 맞추기" 확인 단계가 모두 이 12단어를 다룹니다. 이 자리 밖에서 12단어를 입력하라는 화면은 지갑 앱이 아닙니다.

**오늘 실천 습관 1개:** 12단어를 묻는 메시지 유형 세 가지(가짜 고객센터 / 에어드랍 지갑 연결 / "복구 도우미")를 위 표에서 소리 내어 읽고, "12단어를 입력하는 화면은 지갑 앱을 처음 만들 때 한 번뿐"이라고 스스로 말해 보세요. 지금 12단어를 화면에 다시 띄우거나 옮겨 적을 필요는 없습니다.

> 12단어가 폰 사진첩·메모 앱·메신저에 들어 있는 것을 이미 알고 있다면, **오늘 서둘러 지우지 마세요.** 종이로 옮겨 적고 → 그 종이만으로 지갑이 복구되는지 어른과 함께 오프라인에서 확인하고 → 복구가 된 뒤에 그 파일을 지우는 순서로만 하세요. 순서를 바꾸면 옮겨 적기에 실패했을 때 지갑을 영구히 잃습니다. 이 코스 자체는 [START-HERE.md](../../START-HERE.md)의 약속대로 아무것도 보내지 않고 화면만 봅니다.

## 🛡️ 안전 규칙 카드 <a id="card"></a>

**규칙 1. 열쇠(12단어)는 나만 안다. 고객센터도 모른다.**

**해야 할 것**
- ✅ 12단어는 앱이 처음 보여 줄 때, 그 자리에서 종이에 적는다.
- ✅ 종이는 집 안 두 곳에 나눠 두고, 순서와 언어(한국어/영어)를 함께 적는다.
- ✅ 12단어를 묻는 사람·사이트·채팅방은 그 자리에서 대화를 끝낸다. 고객센터도 12단어를 모른다.

**절대 하지 말 것**
- ❌ 사진·메모 앱·메신저·이메일·클라우드에 12단어를 저장하지 않는다.
- ❌ "고객센터", "복구 도우미", "에어드랍"이 묻는 칸에 12단어를 넣지 않는다.
- ❌ 인터넷에 떠도는 샘플 12단어(abandon … about 등)나 화면에 찍혀 남은 12단어를 내 지갑으로 쓰지 않는다.
