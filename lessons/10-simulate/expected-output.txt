[3] 잔고 초과 transfer 리허설 — 실패하는 봉투는 리허설에서 걸러진다
  내 USDT 잔고: 19589.654444 USDT (19,589,654,444 최소 단위)
  리허설 금액: 19589.654445 USDT (잔고 + 1 최소 단위)
  tronweb 예외: REVERT opcode executed
  ✅ REVERT opcode executed — 컨트랙트가 "잔고 부족"으로 되돌렸습니다. 리허설이라 아무 비용도 안 들었습니다.
  노드 원본 result: {"result":true,"message":"REVERT opcode executed"}
  노드 원본 energy_used: 1,984 (REVERT 까지 실행하는 데 쓴 에너지)
  노드 원본 constant_result: [""]
  message 해석: REVERT opcode executed — 노드는 "실행은 했다(result:true)"고 하면서 message 로 REVERT 를 알립니다. 진짜 성공 판단은 message 유무입니다.
  ⚠️  이 봉투를 리허설 없이 실제로 보냈다면: REVERT 로 실패하고도 실행에 쓴 에너지·대역폭만큼 수수료가 나갑니다. 실패는 공짜가 아닙니다.
  💬 tronweb 은 result.message 가 있으면 throw. 노드 원본은 { result: { result: true, message: "REVERT opcode executed" }, energy_used }. 직접 fetch 하면 message 를 그대로 볼 수 있다.

[4] 필요 에너지 추정 (estimateEnergy) → feeLimit 계산
  estimateEnergy.energy_required: 21,975
  리허설 energy_used 와 비교: 14,650 vs 21,975 → 이번 실행에서는 estimateEnergy 가 더 큰(보수적인) 값을 냈습니다. feeLimit 은 큰 쪽으로 잡습니다.
  에너지 가격(getEnergyFee): 100 sun/energy
  에너지 스테이킹이 없을 때 소각: 21,975 × 100 sun = 2,197,500 sun (2.1975 TRX)
  feeLimit = 소각 × 1.2: 2,637,000 sun (2.637 TRX)
  트랜잭션에 넣는 값: { feeLimit: 2637000 }  // sun 단위
  ✅ feeLimit 은 "이 호출에 최대 얼마까지 태워도 되나"의 상한입니다. 너무 작으면 실패, 너무 크면 실패 시 그만큼 잃을 수 있습니다.
  💬 feeLimit 은 에너지 소각 상한(sun). 스테이킹 에너지가 있으면 그만큼은 소각되지 않는다. 대역폭 비용은 feeLimit 과 별개.
