## 🔍 원리 들여다보기 <a id="why"></a>

### 비유 → 정식 용어

| 비유 | 정식 용어 | 스크립트에서 보이는 자리 |
|---|---|---|
| 종이 입장권 | 대역폭(Bandwidth), 단위 byte, 계정마다 하루 600 무료 | `freeNetLimit: 600` |
| 기계 입장권 | 에너지(Energy), 컨트랙트 실행에 소모, 무료 없음 | `EnergyLimit` (스테이킹 없으면 0) |
| 사탕상자 태우기 | TRX 소각(burn): 대역폭 1000 sun/byte, 에너지 100 sun/energy | `getTransactionFee`, `getEnergyFee` |
| 맡기기 | 스테이킹(Stake 2.0, `freezeBalanceV2`) | `NetLimit`, `EnergyLimit` |
| 자판기 | 스마트컨트랙트(예: USDT TRC-20) | `estimateEnergy(...)` |
| 새 친구 우편함 만들기 | 계정 활성화, 1 TRX | `getCreateNewAccountFeeInSystemContract` |

### 왜 "건수"가 아니라 "바이트"로 셀까요?

대역폭은 트랜잭션의 **크기**만큼 소모됩니다. 단순 TRX 전송은 `raw_data_hex` 133 bytes + 서명 65 bytes = 198 bytes이고, 실제 영수증에서 직접 관찰된 값은 `net_fee: 266,000 sun`입니다. 1 byte가 1000 sun이므로 266,000 ÷ 1000 = **266 bytes**로 역산됩니다(protobuf 봉투 포함). 하루 600으로는 2건(266 × 2 = 532)까지 무료이고, 세 번째 전송은 266 × 1000 sun = 0.266 TRX를 소각합니다. 남은 68 bytes로 부분 상쇄되는지는 (확인 필요) — 정산은 자기 영수증의 `net_usage`/`net_fee`로 확인하세요.

에너지는 컨트랙트 코드가 얼마나 많은 명령을 실행했는지로 정해집니다. USDT 1개를 이미 USDT를 가진 주소로 보내면 21,975 energy, 스테이킹이 없으면 21,975 × 100 sun = 2.1975 TRX가 소각됩니다.

### 왜 그렇게 설계했을까?

"거래마다 수수료를 내라(gas)" 대신 "하루 600 bytes는 공짜, 컨트랙트는 스테이킹으로"라는 설계는 **자주 쓰는 사람이 미리 TRX를 맡겨 두면 매번 수수료를 안 내도 되게** 하려는 선택입니다. 대신 처음 온 사람은 당황합니다. 여러분이 설계자라면 어느 쪽을 고르고, 그 이유를 숫자(600, 266, 21,975)로 어떻게 설명하겠습니까?

### 비유의 한계 한 줄

입장권은 장수로 세지만 대역폭은 봉투 크기(바이트)만큼 소모되고, 기계 입장권은 미리 사 두는 것이지만 에너지는 없으면 그 자리에서 TRX를 태워 대신합니다.

### [1/6] getAccountResources — 내 자원 한도와 사용량

```
  무료 대역폭(종이 입장권): 0 / 600 사용 → 남은 600 bytes (매일 새로 채워짐)
  에너지(기계 입장권): 0 / 1323765 사용 → 남은 1323765 (무료 없음)
```

`freeNetLimit`은 항상 600. `NetLimit`/`EnergyLimit`은 스테이킹으로 얻은 몫이고, 데모 주소는 누군가 스테이킹을 해 두어 에너지 한도가 약 132만입니다. 사용량이 0이면 노드가 `freeNetUsed`·`NetUsed`·`EnergyUsed` 필드를 **생략**하므로 스크립트는 `res.freeNetUsed ?? 0` 처럼 받습니다.

### [2/6] getChainParameters — 가격표와 변경 이력

```
  getTransactionFee (대역폭 1 byte 가격): 1,000 sun (0.001 TRX)
  getEnergyFee (에너지 1 단위 가격): 100 sun (0.0001 TRX)
  대역폭 가격 이력: 4번 변경(초기값 10 sun 포함 5항목), 현재 1000 sun/byte (마지막 변경 2021-07-14 09:10 UTC)
```

가격은 상수가 아니라 체인 파라미터입니다. `getBandwidthPrices()`/`getEnergyPrices()`는 `"타임스탬프:가격,…"` 문자열을 돌려주므로 첫 항목이 초기값, 마지막 항목이 현재 가격입니다(항목 수 − 1 = 변경 횟수). 활성화·메모 수수료 등 나머지 4줄은 expected-output.txt에 있습니다.

### [3/6] sendTrx 로컬 빌드 — 봉투 크기와 대역폭 소각

```
  raw_data + 서명: 198 bytes
  실제 체인 receipt 관찰값: net_fee 266,000 sun = 266 bytes × 1000 sun (protobuf 봉투 포함)
  무료 대역폭을 쓴 경우: net_usage 에 바이트가 적히는지는 확인 필요 — 정산은 내 receipt 로 확인하세요
  하루 600 bytes 로 가능한 단순 전송: 약 2건
```

`sendTrx(to, sun, from)`은 최근 블록 참조(`ref_block_*`)만 받아 오는 **미서명 객체**를 만듭니다. 수신자는 같은 니모닉의 index 1 주소입니다(자기 자신에게는 빌드가 거부되므로). 로컬 198 bytes는 하한이고, 과금 근거는 영수증 값입니다.

### [4/6] estimateEnergy — USDT 전송 에너지와 소각 TRX

```
  USDT 를 이미 가진 주소로 (TSeJkUh4Qv67VNFwY8LaAxERygNdy6NQZK): energy_required 21,975 → 스테이킹 없으면 21975 × 100 sun = 2,197,500 sun (2.1975 TRX) 소각
  USDT 가 0 인 새 주소로 (TGVURycDcx7pEoD8jDwPd3vprTLDJrHHZm): energy_required 37,063 → 스테이킹 없으면 37063 × 100 sun = 3,706,300 sun (3.7063 TRX) 소각
  에너지 잔량과 비교: 남은 에너지 1323765 → 스테이킹 에너지로 충분
```

```js
const params = [{ type: 'address', value: to }, { type: 'uint256', value: 1_000_000 }];
const est = await tronWeb.transactionBuilder.estimateEnergy(NILE.usdt, 'transfer(address,uint256)', {}, params, address);
// est.energy_required × getEnergyFee = 소각 sun
```

새 주소는 `TronWeb.createRandom()`으로 매 실행 바뀝니다. 조회 주소에 USDT가 없으면 리허설이 REVERT로 실패하므로 try/catch로 안내만 합니다.

### [5/6]·[6/6] 시나리오 계산표와 계정 활성화

```
  USDT 보내기 (무료 대역폭 있음) → 불가능: 바이트는 무료 600 으로 되지만 에너지 21975 을 태울 TRX 가 0
  해결책 → TRX 를 먼저 채우기: 최소 2.1975 TRX(에너지) + 여유분, 대역폭까지 태우면 + 약 0.266 TRX
  새 주소 TGVURycDcx7pEoD8jDwPd3vprTLDJrHHZm: getAccount → {} (활성화 안 됨)
  이 주소로 처음 TRX 를 보내면: 활성화 비용 1,000,000 sun (1 TRX) 가 추가로 듭니다 (getCreateNewAccountFeeInSystemContract)
```

`getAccount`가 빈 객체 `{}`면 한 번도 TRX를 받은 적 없는 주소이고, 레슨 6에서 전송 전 경고로 재사용합니다. 나머지 행은 expected-output.txt `[5]`·`[6]`에 있습니다.

### 트론 vs EVM 차이

| 항목 | 트론 (Nile) | EVM (BTTC Donau, 레슨 11) |
|---|---|---|
| 수수료 단위 | 대역폭(byte) + 에너지 | gas |
| 무료 몫 | 대역폭 하루 600 bytes/계정 | 없음 |
| 미리 확보 | TRX 스테이킹으로 자원 획득 | 없음(매번 gasPrice × gas) |
| 부족할 때 | TRX 소각(1000 sun/byte, 100 sun/energy) | 잔고 부족이면 전송 자체 실패 |
| 상한 | `feeLimit`(sun 단위 정수) — 에너지 소각 상한 | `gasLimit` |
| 새 계정 | 처음 받을 때 활성화 1 TRX | 없음 |

### 함정 1개

## 🏠 내 생활에서는 <a id="life"></a>

지갑 앱(TronLink 등)의 계정 화면 상단에는 **대역폭**과 **에너지** 게이지가 있습니다. "대역폭 600/600"은 오늘 무료 몫을 아직 안 쓴 것이고, "에너지 0"은 고장이 아니라 스테이킹을 안 한 기본 상태입니다. USDT를 보낼 때 앱이 "수수료 약 N TRX"라고 알려 주는 것은 부족한 에너지를 TRX로 태우겠다는 뜻이니, 보내기 전에 TRX 잔고가 그 이상인지 먼저 확인하세요. 거래소에서 USDT만 받고 TRX를 한 개도 안 받았다면 전송이 되지 않으니, 처음에는 TRX를 소량 함께 받아 두세요.

앱에서 이 개념이 보이는 자리: 계정 화면 상단의 게이지 두 개, 전송 확인 화면의 "예상 수수료", 그리고 스테이킹(자원 관리) 메뉴입니다. 세 곳의 숫자가 서로 맞는지 보는 습관을 들이세요.

| 이런 요청이 오면 | 사기인가? | 이유 |
|---|---|---|
| "USDT 전송이 안 되네요. 에너지를 넣어 드릴 테니 복구 구문(12단어)을 알려 주세요" | 예 | 에너지를 넣어 주는 일에 12단어는 전혀 필요 없습니다. 12단어를 묻는 순간 사기입니다 |
| 앱이 수수료(TRX) 부족을 안내함 | 아니오 | 규칙 4 그대로입니다. TRX를 소량 채우면 됩니다 |
| "이 링크에서 지갑을 연결하면 에너지를 무료로 드립니다" (낯선 사이트의 서명 요청) | 예 | 에너지를 준다며 서명(승인)을 받아 가는 유형입니다. 읽을 수 없는 서명 요청은 거절하세요 |

**사기 유형 1개 — 에너지 대여 미끼**: 이 강의는 에너지 대여 서비스를 권하지 않습니다. 에너지가 필요하면 자기 지갑에서 TRX를 스테이킹하세요. "에너지를 싸게 빌려 드립니다"라며 지갑 연결·서명·복구 구문을 요구하는 화면은 그 순간부터 사기입니다.

**오늘 실천 습관 1개:** 지갑 앱을 열어 세 줄만 확인하세요.

1. 대역폭 게이지: 오늘 무료 몫이 남아 있는지 봅니다.
2. 에너지 게이지: 0이어도 정상입니다. 0이면 TRX가 대신 소각됩니다.
3. TRX 잔고: "USDT 한 번 보낼 만큼(앱이 안내하는 수수료 이상)" 있는지 봅니다. 없으면 보내기를 누르기 전에 TRX부터 채웁니다.

## 🛡️ 안전 규칙 카드 <a id="card"></a>

**규칙 4. USDT만 있고 TRX가 0이면 아무것도 못 보낸다. 연료(입장권)가 먼저다.**

**해야 할 것**
- ✅ 보내기 전에 TRX 잔고와 대역폭·에너지 게이지를 먼저 본다.
- ✅ USDT를 받을 지갑에는 TRX를 소량 함께 넣어 둔다.
- ✅ 처음 보내는 주소는 활성화 비용(1 TRX)이 더 드는지 확인한다.

인쇄해서 붙이는 한 줄
- 🔖 종이 입장권은 하루 600, 기계 입장권은 공짜 없음. **TRX가 0이면 아무것도 못 보낸다.**

**절대 하지 말 것**
- ❌ "에너지 넣어 줄게"라며 12단어를 묻는 사람에게 답하지 않는다.
- ❌ 에너지·수수료를 준다는 낯선 사이트의 서명 요청에 도장 찍지 않는다.
- ❌ 앱이 "수수료가 부족합니다"라고 하면 억지로 다시 보내지 않는다. TRX부터 채운다.
