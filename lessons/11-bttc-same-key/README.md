## ✋ 손으로 해보기 <a id="hands"></a>

**활동: "나라 맞추기" 카드 놀이** (20~25분, 4~6명 한 모둠 / 자세한 진행은 [activity.md](./activity.md))

- 준비물: 나라 카드 3장(TRON / BTTC / 다른 나라), 우편함 번호 카드 12장, 옆 나라 봉투 워크시트 4장, 색연필 2색, 열쇠 모양 종이 1장.
- 역할: 토리(번호 카드를 뽑아 나라 카드 위에 올린다) · 비티("봉투에 나라 이름 썼어? 글자까지 똑같이!"만 말한다) · 장부지기 2명(TRON 장부·BTTC 장부를 한 장씩 들고 자기 나라 봉투만 적는다) · 여우 씨(선택, "0x 면 다 같은 나라야"라고만 말한다).
- 진행 ① **모양으로 나누기** — T로 시작하고 34글자면 TRON 카드 위에, 0x로 시작하고 42글자면 일단 BTTC 카드 위에 올립니다.
- 진행 ② **뒤집어 보기** — 0x 카드 뒷면에 나라 이름이 적혀 있습니다. 어떤 카드는 "BTTC", 어떤 카드는 "다른 나라"입니다. 모양이 같은데 나라가 다른 카드를 옮깁니다.
- 진행 ③ **같은 열쇠 찾기** — 토리의 T 카드와 0x 카드가 한 쌍입니다. 장부지기 둘은 같은 우편함을 적되 사탕 수는 나라마다 따로 적습니다.
- 진행 ④ **봉투 쓰기** — 나라 이름 칸을 비우면 장부지기 둘 다 "우리 나라 봉투 아님" 하고 돌려줍니다.

**놀이터 링크:** [우편함 번호 엑스레이 (T ↔ 41 ↔ 0x)](../../playground/address-xray.html) — 이 카드 놀이를 화면에서 그대로 합니다. T주소와 0x주소가 같은 20바이트인 것을 바로 보여 줍니다(ethers 를 CDN 에서 받으므로 **인터넷이 필요**합니다).

**핵심 카드 3장 (앞면만 보면 절대 못 가름)**

| 카드 | 앞면(번호) | 뒷면(나라) | 앞면이 똑같은 카드 |
|---|---|---|---|
| 7 | `0xC8599111…74aD78A` | 다른 나라 | 2번 = BTTC, 토리의 우편함 |
| 9 | `0xb6E708a3…9F052A8` | 다른 나라 | 4번 = BTTC, index 1 우편함 |
| 12 | `0x9858EfFD…caEda94` | 다른 나라 | 5번 = BTTC, 같은 주문 다른 길(60') |

**무장비 5분 버전 — 나라 이름 외치기**

진행자가 주소 모양을 말합니다. "T로 시작, 34글자!" → 모두 "트론!" / "0x로 시작, 42글자!" → 모두 "어느 나라?" 하고 되묻습니다. 0x 모양만 듣고 바로 "BTTC!"를 외친 사람은 한 판 쉽니다. 진행자가 "봉투에 BTTC 라고 써 있어" 하면 그제야 "BTTC!", "다른 나라라고 써 있어" 하면 "다른 나라!" 하고 외칩니다. 다섯 번 반복하고, 마지막에 "왜 0x만 듣고는 나라를 못 맞췄을까?"를 한 사람씩 말합니다.

## 🔍 원리 들여다보기 <a id="why"></a>

### 비유는 이렇게 바뀝니다

| 비유 | 정식 용어 | 스크립트에서 보이는 자리 |
|---|---|---|
| 옆 나라 | BTTC (EVM 호환 체인, Donau 테스트넷) | 머리 부분 `chainId 1029` |
| 나라 이름 | 네트워크(chainId) | `[3] chainId`, `[4] 네트워크` |

### 실험 1 — 출력에서 한 줄 찾기

`[3]` 블록에서 `nonce (이더 경로): 7` 줄을 찾으세요. 이더리움 경로 주소(0x9858…)는 Donau 에서 이미 7번 봉투를 보냈다는 뜻입니다. 같은 블록의 `nonce (트론 경로): 0` 은 한 번도 보낸 적이 없다는 뜻이고, 그래서 `[4]` 미리보기의 `nonce 0` 이 됩니다.

트론에는 이 숫자가 아예 없습니다. 레슨 6 미리보기에서 `유효기간 60초` 가 있던 자리에 이번엔 `유효기간 없음` 이 찍힌 것과 짝을 이룹니다. 두 나라가 "같은 봉투를 두 번 넣기"를 서로 다른 방법으로 막는다는 뜻입니다.

### 실험 2 — 환경변수 바꿔 보기

```bash
AMOUNT_BTT=1 npm run l11
```

`[3]` 의 `필요 합계` 가 `189.001 BTT` 에서 `190.0 BTT` 로 바뀝니다. 금액은 1000배가 됐는데 합계는 1 만 늘었습니다. 수수료 `21000 gas × 9000000000000000 wei = 189.0 BTT` 는 금액과 무관하게 같기 때문입니다.

트론에서 "사탕 1알을 보내도 우표는 똑같이 든다"고 했던 것과 같은 구조인데, 단위가 sun(6자리)이 아니라 wei(18자리)라 숫자가 훨씬 길어 보입니다.

### 왜 그렇게 설계했을까?

BTTC 는 왜 chainId 를 서명 안에 넣을까요? 같은 열쇠가 여러 EVM 나라에서 통하기 때문입니다. chainId 가 없으면 옆 나라에서 찍은 봉투를 다른 나라 우체통에 그대로 넣을 수 있습니다(재생). chainId 1029 가 서명에 들어가면 그 봉투는 1029 나라에서만 유효합니다.

여기서 두 가지를 구분해야 합니다. 봉투에 적힌 chainId 가 다르면 그 봉투는 **그 나라에서 무효**가 되고, 엉뚱한 나라로 배달되지는 않습니다. 실제로 자산을 잃는 경로는 서명 재생이 아니라, 주소만 맞고 **나라를 잘못 골라 다른 장부에 기록될 때**입니다(🏠 의 출금 화면 이야기가 이것입니다). 그래서 "나라 이름을 글자까지 맞춘다"는 규칙은 지갑 앱의 잔소리가 아니라 서명 규칙 그 자체이면서, 동시에 출금 화면에서 고르는 칸이기도 합니다.

**비유의 한계 1줄:** 나라 이름은 비슷해도 되지만 네트워크는 chainId 숫자와 주소 표기까지 하나도 다르면 안 됩니다. 0x 주소 모양만으로는 어느 EVM 나라인지 알 수 없습니다.

## 💻 코드로 확인하기 <a id="code"></a>

### 실행

```bash
npm run l11                              # 미리보기(기본). [5]에서 멈추고 아무것도 보내지 않는다
AMOUNT_BTT=1 npm run l11                 # 금액 바꾸기

```

실제 전송(`SEND_TX=true`)은 **이 저장소의 어느 경로에서도 하지 않습니다.** 모든 레슨은 미리보기(`SEND_TX=false`)로만 실행합니다. `lib/guard.js` 의 `assertCanSend` 가 어떤 조건에서 막는지는 아래 "SEND_TX=true 일 때의 흐름"과 코드로 읽어 확인하세요.

- `MNEMONIC` 이 없으면 데모 니모닉으로 자동 대체하고 "데모 모드" 경고를 먼저 찍습니다(읽기·오프라인 서명·미리보기 레슨).
- 네트워크는 `lib/bttc.js` 의 `DONAU`(`https://pre-rpc.bt.io/`, chainId 1029)만 씁니다. 메인넷 호스트는 `assertCanSend` 가 막습니다.
- **전체 출력은 `expected-output.txt` 에 그대로 있습니다.** 아래 인용은 핵심 줄만 골랐습니다.

### 단계별 출력 해설

`[1/6]` 같은 열쇠, 두 나라 — 트론 경로(195') 개인키를 `ethers.Wallet` 에 넣은 주소, T주소에서 `41` 을 뗀 주소, `lib/wallet` 의 `evmAddress` 세 값이 모두 `0xC8599111F29c1e1E061265b4AF93eA1F274aD78A` 로 같습니다(`TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH` 의 hex 는 `41c8599111…4ad78a`).

```js
const wallet = new ethers.Wallet('0x' + me.privateKey);          // 0x 를 붙여도 되지만 필수는 아니다
const hex41 = TronWeb.address.toHex(me.address);                 // '41' + 40hex
const evmFromT = ethers.getAddress('0x' + hex41.slice(2));       // EIP-55 체크섬 표기
```

`[2/6]` 이더리움 경로 — 같은 12단어라도 `m/44'/60'/0'/0/0` 으로 만들면 전혀 다른 열쇠·주소입니다(`0x9858EfFD232B4033E47d90003D41EC34EcaEda94`, T 표기 `TPrkFhZ8LH8Mruco8vXyA496TaeFBrbmeU`).

`[3/6]` Donau 읽기 — `getNetwork`·`getBlockNumber`·`getBalance` ×2·`getTransactionCount` ×2·`getFeeData` 를 `Promise.all` 로 한 번에 읽습니다. `maxFeePerGas` 가 `null` 이라 legacy(type 0)만 씁니다. 데모 195' 주소는 0 BTT 라 `estimateGas` 가 `insufficient funds` 예외를 던지고(이번 실행에서 관찰, 확인 필요) 고정값 21000 gas 로 대체합니다. 레슨 10 표의 `21,000 gas` 는 잔고가 있는 주소에서 나온 값이고, 잔고 0 인 데모 195' 주소에서는 리허설 자체가 먼저 넘어집니다. `최신 블록` 과 두 잔고·nonce 는 실행할 때마다 달라집니다.

```
  chainId: 1029 (= DONAU.chainId, 나라 이름이 맞다)
  잔고 (트론 경로 0xC85991…): 0.0 BTT (0 wei)
  잔고 (이더 경로 0x9858Ef…): 166.422670839000709877 BTT
  nonce (트론 경로): 0 ← 이 계정이 지금까지 보낸 트랜잭션 수. 다음 봉투의 번호
  ⚠️  estimateGas 실패: insufficient funds → 단순 전송 고정값 21000 gas 로 계산합니다.
  예상 수수료: 21000 gas × 9000000000000000 wei = 189000000000000000000 wei = 189.0 BTT
```

`[4/6]` 오프라인 조립·서명 — 봉투에 `nonce`, `gasPrice`, `chainId` 가 들어가고 유효기간은 없습니다. 서명 전 48 bytes, 서명 후 113 bytes 이고, hash 는 **서명된** RLP 의 keccak256(`ethers.keccak256(signedRaw)`)이라 서명 뒤에야 정해집니다. 트론 txID 는 서명 전 `raw_data` 의 sha256 이었습니다.

```
  │ nonce       0
  │ gasPrice    9000000000000000 wei
  │ 유효기간    없음 (nonce 로 순서·중복을 막는다. 트론의 60초 expiration 과 다름)
  │ hash        0x9f0282d37464c44610e5cf36cf99557d5b885758dca6d44ed8f3d8874f3fe763
```

`[5/6]` guard — 레슨 6 과 같은 관문이지만 `host: DONAU.rpcUrl` 을 넘깁니다. `SEND_TX=false` 면 `GuardError` 로 멈추고(`🛑 미리보기 종료`) exit 0 입니다. BTTC 메인넷 호스트(`rpc.bittorrentchain.io`)도 guard 의 차단 목록에 있습니다.

`[6/6]` 비교표 — 미리보기 종료 뒤에도 출력됩니다. 8행 전문은 `expected-output.txt` 에 있고, 핵심은 순서·중복(expiration vs nonce), 최소 단위(6자리 vs 18자리), 해시 시점(서명 전 vs 서명 후) 세 줄입니다.

### SEND_TX=true 일 때의 흐름 (작성자·검수자는 실행하지 않음)

아래 표는 **실제 출력이 아니라 코드에서 옮긴 흐름**입니다. `lib/guard.js` 의 카운트다운은 `process.stdout.write` 로 들여쓰기 없이 `⚠️  3초 뒤 …` 형태로 찍힙니다.

| 단계 | 코드가 하는 일 |
|---|---|
| `[5]` | `assertCanSend` → 카운트다운 뒤 `✅ 관문 통과` |
| `[6]` | 받는 사람이 나 자신이거나 잔고가 `금액 + gas × gasPrice` 보다 적으면 여기서 멈춥니다(브로드캐스트 안 함). 그 밖에는 `broadcastTransaction` → `wait(1, 30000)` → 블록·status·gasUsed·실제 수수료. 30초가 지나면 `TIMEOUT` 예외를 잡아 "이미 보냈을 수 있으니 탐색기에서 확인" 으로 안내하고, 실패로 표시하지 않습니다 |

실제 출력은 `.env` 에 연습용 니모닉을 넣고 Donau faucet(`https://testfaucet.bt.io/#/`)에서 BTT 를 받은 뒤 직접 확인하세요.

### 트론 vs EVM 차이

| | 트론 (Nile) | BTTC (Donau, EVM) |
|---|---|---|
| 개인키 입력 형식 | `TronWeb.address.fromPrivateKey('64hex')` — `0x` 를 떼야 한다 | `new ethers.Wallet(64hex)` — `0x` 있어도 없어도 동작(ethers 6 에서 확인) |
| 자기 자신에게 전송 | 거부 (`Cannot transfer TRX to the same account`, 확인됨) | 별도 검증 안 함(확인 필요). 스크립트는 경고 후 미리보기까지만 진행 |
| 브로드캐스트 | `sendRawTransaction(signedTx)` → `{ result, txid }` 또는 `{ code, message }` | `broadcastTransaction(raw)` 호출(반환·실패 형태 확인 필요) |
| 영수증 | `getTransactionInfo(txid)` 폴링(빈 `{}` 가능) | `response.wait(1, 30000)` → receipt, 시간 초과 시 code `TIMEOUT` 예외(확인 필요) |
| 잔고 부족 리허설 | `triggerConstantContract` → `REVERT opcode executed` | `estimateGas` → `insufficient funds` 예외(확인 필요) |

### 함정 1개

**같은 12단어를 제대로 넣었는데 BTTC 잔고가 0 으로 보이는 함정**입니다. `[2]` 처럼 파생 경로가 195' 와 60' 두 갈래라, EVM 지갑 앱은 60' 주소(0x9858…)를, 트론 지갑 앱은 195' 주소(0xC859…)를 기본으로 보여 줄 수 있습니다(확인 필요). 데모 니모닉에서 Donau BTT 가 있는 쪽은 60' 주소이고 195' 주소는 0 BTT 입니다(`[3]` 의 두 잔고 줄). 그래서 잔고가 0 으로 보일 때 먼저 의심할 것은 12단어가 아니라 경로입니다. 덧붙여 `TronWeb.address.fromPrivateKey` 에는 `0x` 를 뗀 hex 를 넣어야 합니다(`ethers.Wallet` 은 `0x` 가 있어도 없어도 같은 지갑을 만듭니다).

### 도전

- (쉬움) `TO` 에 T주소를 넣고 실행해 머리 부분의 `받는 사람` 줄이 `T주소 … → 0x 로 변환` 으로 바뀌는지 확인하세요. `resolveTo` 가 `ethers.isAddress` 와 `TronWeb.isAddress` 를 어떤 순서로 검사하는지 읽어 보세요.
- (어려움) `[4]` 의 `txRequest` 에서 `chainId` 를 `1030` 으로 바꿔 서명한 뒤 `ethers.Transaction.from(signedRaw).chainId` 와 `hash` 가 어떻게 달라지는지 출력하세요(브로드캐스트는 하지 않습니다). "나라 이름이 서명 안에 들어간다"를 숫자로 확인하는 과제입니다. `lib/` 는 건드리지 않습니다.

## 🏠 내 생활에서는 <a id="life"></a>

- 지갑 앱(TronLink 등)에서 네트워크를 TRON 에서 BTTC 로 바꾸면 같은 계정의 주소가 `T…` 에서 `0x…` 로 바뀌어 보입니다(앱 버전마다 화면이 다를 수 있음, 확인 필요). 주소 모양이 달라져도 열쇠와 주인은 같습니다. 잔고는 나라마다 따로입니다.
- 거래소 출금 화면에는 대개 "주소"와 "네트워크" 두 칸이 있습니다. 네트워크 칸의 선택지가 TRON(TRC20), BTTC, ERC20 처럼 여러 개일 때(표기는 거래소마다 다름, 확인 필요), **상대가 알려 준 네트워크와 글자까지 같은 것**을 고르세요. 0x 주소는 여러 EVM 네트워크에서 같은 모양이라 "주소가 맞으니 됐다"가 통하지 않습니다.
- 네트워크를 잘못 고르면 돈이 사라지는 것이 아니라 **다른 장부에 기록**됩니다. 그 네트워크의 주소를 내가 못 여는 경우(거래소 주소 등)에 찾기 어려워지는 것입니다. 그래서 "어느 장부에 적힐지"를 보내기 전에 정합니다.
- 처음 쓰는 네트워크·주소 조합이라면 레슨 6 대로 소액을 먼저 보내고, 상대 네트워크의 탐색기에서 도착을 확인한 뒤 나머지를 보내세요.
- 지갑 앱을 12단어로 새로 복구했는데 BTTC 잔고가 0 으로 보이면, 12단어가 틀린 게 아니라 앱이 보는 **파생 경로**가 다를 수 있습니다(확인 필요). 12단어를 다시 입력하거나 어딘가에 붙여 넣기 전에, 앱의 "고급 설정 · 경로" 화면부터 확인하세요.
- 네트워크 이름은 캡처해서 보관하세요. 문자로 받은 "BTTC" 와 화면의 선택지를 같은 화면에 놓고 비교하면, 급할 때 바뀐 요청을 알아차리기 쉽습니다.

**이런 요청이 오면 사기인가?**

| 상황 | 사기? | 이유 |
|---|---|---|
| 상대가 "0x 주소니까 아무 네트워크로 보내도 돼요"라고 말함 | 예(또는 무지) | 0x 주소는 여러 나라에서 같은 모양입니다. 네트워크가 다르면 장부가 다릅니다. 글자까지 맞추지 않으면 잃을 수 있습니다 |
| 거래소 출금 화면이 "네트워크를 선택하세요"라고 한 번 더 물어봄 | 아니오 | 정상적인 확인 절차입니다. 상대가 말한 네트워크와 같은지 여기서 맞춥니다 |
| "다른 네트워크로 잘못 보내셨네요. 복구해 드릴 테니 12단어를 알려 주세요" | 예 | 복구를 대가로 12단어를 묻는 순간 사기입니다. 어떤 네트워크든 12단어는 아무에게도 주지 않습니다 |

**사기 유형 1개 — "네트워크 바꿔치기":** 상대가 처음엔 TRON(TRC20) 주소를 주고, 보내기 직전에 "BTTC 로 보내 주세요"라고 바꿔 말합니다. 급하게 네트워크만 바꾸면 주소·네트워크 조합이 틀려 잃을 수 있습니다. 바뀐 요청은 처음부터 다시 확인하고, 소액 먼저 보내세요.

**오늘 실천 습관 1개:** 보내기 전에 상대에게 "네트워크 이름을 글자 그대로 적어 보내 달라"고 하고, 출금 화면의 네트워크 칸과 나란히 놓고 비교하세요.
