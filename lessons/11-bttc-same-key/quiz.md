## 정답과 해설

### 🧒 초등
1. **②** — 옆 나라(BTTC) 번호는 0x로 시작해요. T 번호 안에 숨어 있던 바로 그 번호예요.
2. **②** — 열쇠는 같아도 장부는 나라마다 따로예요. 옆 나라 사탕은 옆 나라 장부에서 봐요. 데모 토리의 옆 나라 잔고는 0 이었어요(`[3]` 잔고 줄).
3. **②** — 0x 모양은 여러 나라가 같이 써요. 봉투에 적힌 나라 이름을 글자까지 맞춰야 해요.
4. **②** — 나라마다 장부가 달라서, 엉뚱한 나라 우체통에 넣으면 아무도 찾아 주지 못해요. 여우 씨 말은 속임수예요.
5. **①** — 옆 나라 봉투에는 순서 번호(nonce)가 있고 유효기간은 없어요. 트론 마을 봉투는 반대예요.

### 🔍 중고등
1. `TronWeb.address.toHex → '41' + 20바이트: 41c8599111…ad78a` 줄과 `'41' 을 떼고 '0x' 를 붙이면: 0xC8599111…D78A` 줄. `41` 은 "트론 주소"라는 표시(프리픽스), 체크섬 4바이트는 오타 검출용이며, 둘을 빼면 EVM 주소와 같은 20바이트만 남습니다.
2. nonce 는 그 계정이 지금까지 보낸 트랜잭션 수이자 다음 트랜잭션의 순번입니다. 트론 경로 주소는 Donau 에서 한 번도 보낸 적이 없고(0), 이더 경로 주소는 7번 보냈습니다. 트론에는 nonce 가 없고 대신 `ref_block_bytes/hash`(최근 블록 참조)와 `expiration`(60초)으로 중복·재생을 막습니다.
3. 1 BTT = 10^18 wei 이므로 189,000,000,000,000,000,000 wei ÷ 10^18 = 189 BTT. 트론은 1 TRX = 10^6 sun(6자리)이라 266,000 sun = 0.266 TRX. 자릿수가 18 대 6 이라 BTTC 쪽 숫자가 훨씬 길어 보이지만 계산 방식은 같습니다.
4. 트론 txID = sha256(raw_data). raw_data 에는 서명이 없으므로 서명 전에 이미 정해지고 서명해도 안 바뀝니다. EVM hash = keccak256(서명된 RLP). 서명값 v,r,s 가 해시 입력에 들어가므로 서명한 뒤에야 정해집니다(`[4]` 서명 전 48 bytes → 서명 후 113 bytes).
5. 서명은 chainId 를 포함한 내용에 찍힙니다. 같은 봉투를 chainId 가 다른 나라에 넣으면 서명이 그 나라 규칙과 맞지 않아 무효가 됩니다. 즉 "어느 나라 봉투인가"가 서명 안에 이미 적혀 있어, 앱이 물어보는 네트워크 칸은 그 서명값을 정하는 입력입니다. 반대로 주소만 같고 chainId 를 잘못 고르면 다른 장부에 기록됩니다.

### 💻 개발자
1. 첫 줄에 `⚠️  MNEMONIC 이 없어 데모 니모닉(abandon … about)으로 진행합니다. 데모 모드 — 조회·오프라인 서명·미리보기만 합니다.` 가 찍히고 나머지는 데모 니모닉으로 똑같이 진행되어 **exit 0** 입니다. 레슨 6 은 실제 전송 레슨이라 MNEMONIC 이 없으면 안내 후 exit 1 로 끝났지만, 이 레슨은 읽기·미리보기 레슨이라 자동 대체합니다.
2. `필요 합계: 190.0 BTT (금액 1 + 수수료 189.0)`. `예상 수수료` 줄은 `21000 gas × 9000000000000000 wei = 189000000000000000000 wei = 189.0 BTT` 그대로입니다. 수수료는 금액과 무관하게 gas × gasPrice 입니다.
3. 데모 트론 경로 주소(0xC859…)의 Donau 잔고가 0 BTT 라서 노드가 리허설(estimateGas) 단계에서 `insufficient funds` 예외를 던집니다(이번 실행에서 관찰, 확인 필요). 스크립트는 catch 에서 `SIMPLE_TRANSFER_GAS = 21000n` 으로 대체하고 계속 진행합니다. 이더 경로 주소(0x9858…)는 약 166 BTT 가 있으니 단순 전송이면 `estimateGas` 가 `21000` 을 돌려줄 것으로 예상됩니다(단순 전송의 고정 gas). 다만 이 주소로 `estimateGas` 를 실제로 호출한 기록은 이번 검증에 없으므로 **직접 실행해 확인 필요**입니다.
4. `받는 사람:   0xb6E708a39781c96Bd399C7657780Ff9Fe9F052A8  ← TO 환경변수(T주소 TSeJkUh4Qv67VNFwY8LaAxERygNdy6NQZK → 0x 로 변환)`. `resolveTo` 는 먼저 `ethers.isAddress`(0x 형식)를 검사하고, 아니면 `TronWeb.isAddress`(T 형식)를 검사해 `TronWeb.address.toHex` → `41` 제거 → `ethers.getAddress` 로 바꿉니다. 둘 다 아니면 `❌ 받는 주소가 올바르지 않습니다` 후 exit 1.
5. `SEND_TX=true` 검사는 통과하지만 다음 검사에서 `데모 니모닉(abandon … about)으로는 전송할 수 없습니다. npm run new-wallet 로 만든 연습용 니모닉을 .env 에 넣으세요.` 가 나옵니다. `GuardError` 이므로 "미리보기 종료" → 비교표 → **exit 0**. 설령 guard 를 통과했더라도 `[6]` 첫머리의 잔고 검사(`balanceWei < valueWei + gasLimit * gasPrice`)가 0 BTT 계정을 막고 faucet 안내 후 exit 1 로 끝냅니다.

### 🏠 일반인
1. BTTC 를 고릅니다. 고르기 전에 상대가 보낸 글자("BTTC")와 화면의 선택지 글자를 나란히 놓고 대조하고, 상대의 주소가 0x 형식인지(BTTC 는 0x)도 확인하세요. 처음 보내는 조합이면 소액 먼저(레슨 6).
2. 틀린 말입니다. 0x 주소는 여러 EVM 네트워크에서 같은 모양이지만 장부는 네트워크마다 따로입니다. 네트워크를 다르게 고르면 다른 장부에 기록되고, 상대가 그 네트워크의 열쇠를 쓰지 않으면 찾지 못할 수 있습니다. 상대에게 네트워크 이름 하나를 글자로 확정해 달라고 하세요.
3. 해킹이 아닐 가능성이 큽니다. BTTC 에서는 같은 열쇠가 0x 주소로 보이고, 잔고는 네트워크마다 따로입니다. TRON 잔고는 TRON 네트워크로 돌아가면 그대로 보입니다. 다만 다른 앱에서 복구했는데 잔고가 0 이면 파생 경로 차이(레슨 2, 이번 레슨 `[2]`)도 의심하세요(확인 필요).
4. 멈추세요. 바뀐 요청은 처음부터 다시 확인합니다. 상대에게 네트워크 이름과 주소를 글자로 다시 보내 달라고 하고, 화면의 네트워크 칸을 새로 대조한 뒤, 소액을 먼저 보내 그 네트워크 탐색기에서 확인하세요. 급하게 바꿔 말하는 것은 "네트워크 바꿔치기" 사기의 흔한 모습입니다.
5. 입력하지 마세요. 어떤 서비스도 12단어를 요구하는 순간 사기입니다. 잘못 보낸 자산은 12단어를 넘긴다고 돌아오지 않고, 넘기는 순간 남은 자산까지 잃습니다. 탐색기에서 어느 네트워크에 기록됐는지 먼저 확인하고, 거래소로 보냈다면 그 거래소의 공식 고객센터(12단어를 묻지 않는 곳)에만 문의하세요.
