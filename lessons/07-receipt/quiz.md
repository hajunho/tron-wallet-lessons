# Lesson 07 확인 문제 — 영수증과 발자국

규칙 7: "보냈다"는 말 대신 txID로 영수증을 본다.

정답과 해설은 맨 아래에 있습니다. 먼저 풀고 나서 확인하세요.

## 🧒 초등 — 그림·상황 고르기

- (가) 몇 번째 장에 적혔는지

## 🔍 중고등 — 이유 쓰기

**중1.** `getTransaction`과 `getTransactionInfo`는 같은 txID를 넣어도 돌려주는 내용이 다릅니다. 각각 무엇을 돌려주는지 한 줄씩 쓰고, "성공했는지"와 "수수료가 얼마인지"는 어느 쪽에서 봐야 하는지 이유와 함께 쓰세요.

**중2.** 이 레슨 영수증(`expected-output.txt`)에 `net_fee: 701000`이 찍혔습니다. 대역폭 가격이 1000 sun/byte일 때 이 봉투는 몇 바이트였을까요? 그리고 하루 600 무료 대역폭이 남아 있었다면 이 값은 어떻게 달라졌을지 이유를 쓰세요.

**중3.** 발자국의 `topics[0]`이 `ddf252ad…b3ef`이면 Transfer 이벤트라고 판단합니다. 컨트랙트 주소가 서로 달라도 이 값이 같은 이유를 쓰세요.

**중4.** 발자국의 `value`가 `1000000000`(raw)으로 나왔습니다. 이것을 "10 개"라고 바로 말하면 안 되는 이유를 쓰고, 무엇을 더 조회해야 하는지 쓰세요.

**중5.** 영수증의 `blockNumber`가 현재 블록보다는 작지만 확정 블록보다는 큽니다. 이 봉투를 "확정됐다"고 해도 될까요? 이유를 쓰세요.

## 💻 개발자 — 출력 예측

```js
const info = await tronWeb.trx.getTransactionInfo(txid);
if (!info || Object.keys(info).length === 0) {
  print.warn('영수증이 아직 비어 있습니다({}). …');
  return;
}
```

**개2.** 단순 TRX 전송(TransferContract)의 영수증에 대해 아래 코드가 출력하는 `receipt.energy_*` 줄은 무엇일까요?

```js
if (energyTotal || energyFee || r.result) { /* energy 5줄 */ }
else { print.info('receipt.energy_*', '없음 — 단순 TRX 전송은 에너지를 쓰지 않습니다'); }
```

**개3.** 어떤 컨트랙트 호출의 영수증이 `{ energy_fee: 509400, energy_usage_total: 5115, net_fee: 539000, result: 'SUCCESS' }`이고 `info.fee`가 `1048400`입니다. 아래 코드는 `✅`와 `⚠️` 중 어느 쪽을 출력할까요?

```js
if ((info.fee ?? 0) === netFee + energyFee) print.ok(`fee = net_fee + energy_fee = …`);
else print.warn(`fee(…) 와 net_fee + energy_fee(…) 가 다릅니다 …`);
```

**개4.** 로그가 `{ address: 'eca9bc82…de05f', topics: ['ddf252ad…b3ef', '0000…3816c99260478b8db06f991d5aae6d1ae27d0041', '0000…18d2…1fc3'], data: '0000…493e0' }` 일 때, 아래 두 줄의 결과를 예측하세요. (`493e0` = 10진수로 300,000)

```js
const from = topicToAddress(log.topics[1]);   // '41' + 뒤 40hex → T주소
const raw = BigInt('0x' + log.data);
```

**개5.** 존재하지 않는 txID를 `TXID=0000…0000`으로 넘겼습니다. 스크립트는 2단계에서 어떤 예외를 잡고, 마지막 줄에 무엇을 출력하며, exit code는 무엇일까요?

## 🏠 일반인 — 상황 판단

**일1.** 거래 상대가 "방금 보냈어요"라며 앱 화면 캡처를 보냈습니다. 캡처에는 "전송 완료"가 크게 적혀 있습니다. 어떻게 하시겠습니까?
- (가) 캡처가 있으니 물건을 보낸다.
- (나) txID(64글자)를 요청해 탐색기에서 SUCCESS와 확정 여부를 직접 확인한 뒤 진행한다.
- (다) 상대에게 내 지갑 복구 구문을 알려 주고 직접 확인해 달라고 한다.

**일2.** 탐색기에서 txID를 검색했더니 결과가 "REVERT"이고 수수료는 나갔습니다. 맞는 설명은?
- (가) 실패했으니 수수료도 돌아온다.
- (나) 토큰은 움직이지 않았고, 수수료만 소각됐다.
- (다) 토큰은 갔는데 표시만 실패다.

**일3.** 상대가 "탐색기가 느려서 아직 안 보이는 거예요. 빨리 물건부터 보내 주세요"라고 재촉합니다.
- (가) 급하니 먼저 보낸다.
- (나) 영수증은 몇 블록(초 단위) 뒤면 나온다. 영수증에 SUCCESS가 보일 때까지 기다린다.
- (다) 수수료를 더 내면 빨라지니 상대에게 수수료를 보낸다.

**일4.** txID를 받아 탐색기에서 봤더니 SUCCESS인데, 토큰 전송 내역(발자국)에 내 주소가 없습니다. 어떤 뜻일까요?
- (가) 내 주소로 온 전송이 아니다. 받는 주소와 토큰 컨트랙트 주소를 다시 확인한다.
- (나) 탐색기 오류이니 상대 말을 믿는다.
- (다) 내 앱을 삭제하고 다시 설치한다.

**일5.** 모르는 사람이 "당신 지갑에 잘못 보냈어요. 이 txID 보세요. 돌려주세요"라며 txID를 보냈습니다. 탐색기에서 그 txID를 보니 내 주소로 들어온 기록이 **없습니다**.
- (가) txID가 있으니 진짜다. 돌려준다.
- (나) 장부에 없는 입금은 없는 것이다. 응답하지 않는다.
- (다) 상대에게 내 잔고 캡처를 보내 준다.

## 정답과 해설

### 초등
- **초1. (나)** — "보냈다"는 말은 말일 뿐이에요. 봉투 번호로 영수증을 찾아요. (다)는 절대 안 돼요. 노드 아저씨도 주문을 안 물어봐요.
- **초2. (다)** — 영수증에는 장 번호, 시각, 요금, 결과, 발자국이 있어요. 12단어 주문은 어디에도 적히지 않아요.
- **초3. (가)** — 실패해도 우표 요금은 나가요. 사탕은 안 가요.
- **초4. (나)** — 발자국은 자판기(컨트랙트)를 쓴 봉투에만 남아요. 사탕상자를 그냥 보내면 발자국이 없어요.
- **초5. (나)** — 영수증은 몇 장 뒤에 나와요. 빈 종이({})는 "아직"이라는 뜻이에요. 여우 씨는 안 돼요.

### 중고등
- **중1.** `getTransaction`은 봉투 자체(raw_data·signature)와 `ret[0].contractRet`을 돌려주고, `getTransactionInfo`는 장부에 적힌 뒤의 영수증(blockNumber, fee, receipt, log)을 돌려줍니다. 결과는 양쪽 다 보이지만(`contractRet`, `receipt.result`) 수수료와 블록 번호는 영수증에만 있으므로 최종 확인은 `getTransactionInfo`로 합니다.
- **중2.** 701000 ÷ 1000 = 701 bytes. 무료 대역폭이 남아 있었다면 TRX를 태우지 않아 `net_fee`는 없고 대신 `net_usage`(바이트 수)가 찍혔을 것입니다(**확인 필요** — 무료 대역폭을 쓴 경우 `net_usage`가 찍히고 `net_fee`가 없는지는 이번 검증에서 확인하지 못했습니다. [CHEATSHEET.md](../../CHEATSHEET.md)의 "(확인 필요)" 표 참조).
- **중3.** `topics[0]`은 이벤트 서명 문자열 `Transfer(address,address,uint256)`의 해시입니다. 컨트랙트 주소가 아니라 이벤트의 이름과 인자 타입에서 나오므로, 어느 컨트랙트든 같은 이름의 이벤트면 같은 값입니다. 그래서 컨트랙트 주소는 `log.address`로 따로 봅니다.
- **중4.** 로그의 `value`는 최소 단위(raw)이고 decimals 정보가 로그에 없습니다. 컨트랙트의 `decimals()`를 조회해야 사람이 읽는 수가 됩니다. decimals가 6이면 1000 개, 18이면 0.000000001 개로 전혀 다릅니다.
- **중5.** 아직 확정이 아닙니다. 장부에 적히긴 했지만 뒤에 붙은 장이 충분하지 않아 확정 블록(solidified) 안에 들어오지 않았습니다. `blockNumber ≤ 확정 블록`이 될 때까지 기다립니다.

### 개발자
- **개1.** `info`는 빈 객체 `{}`일 가능성이 높습니다(방금 들어간 tx는 솔리디티 전). 스크립트는 `⚠️  영수증이 아직 비어 있습니다({}). …` 를 출력하고 `return`으로 끝납니다(exit 0).
- **개2.** 단순 전송 receipt는 `{ net_fee: 266000 }` 또는 `net_usage`만 있어 `energyTotal`, `energyFee`, `r.result`가 모두 비어 있으므로 `receipt.energy_*: 없음 — 단순 TRX 전송은 에너지를 쓰지 않습니다` 한 줄이 출력됩니다.
- **개3.** 539000 + 509400 = 1048400 = `info.fee`이므로 `✅ fee = net_fee + energy_fee = 539000 + 509400 = 1048400 sun` 이 출력됩니다.
- **개4.** `from` = `TronWeb.address.fromHex('413816c99260478b8db06f991d5aae6d1ae27d0041')` = `TF5n96auHbEcTrR5GmY1Qm9XXMbjPe22y9`, `raw` = `300000n`. 컨트랙트 address가 Nile USDT(`TXYZopYRdj2D9XRtbG411XZZ3kM5VkAeBf`)이므로 decimals 6을 적용하면 0.3 USDT. (expected-output.txt의 5단계 log[0]과 같은 값)
- **개5.** `getTransaction`이 `Transaction not found` 예외를 던지고, 스크립트는 이를 잡아 `lesson07 실패: 장부에 없는 txID 입니다 (Transaction not found). 번호를 다시 확인하세요: 0000…` 를 stderr에 출력하며 `process.exitCode = 1`로 끝납니다. (참고: `getTransactionInfo`였다면 예외 없이 `{}`를 돌려줍니다.)

### 일반인
- **일1. (나)** — 캡처는 꾸밀 수 있습니다. txID는 장부와 대조됩니다. (다)는 어떤 경우에도 안 됩니다.
- **일2. (나)** — 실패한 트랜잭션도 수수료는 소각됩니다. 토큰은 움직이지 않았습니다.
- **일3. (나)** — 트론은 3초마다 블록이 붙고 영수증은 몇 블록 뒤면 나옵니다. "느려서"라는 말로 재촉하면 의심하세요. (다)처럼 수수료를 보내 달라는 요청은 사기입니다.
- **일4. (가)** — SUCCESS는 "그 트랜잭션이 성공했다"는 뜻이지 "내게 왔다"는 뜻이 아닙니다. 발자국의 to가 내 주소인지, 토큰 컨트랙트 주소가 진짜인지(레슨 3) 확인하세요.
- **일5. (나)** — 장부에 없으면 받은 것이 없습니다. 돌려줄 것도 없습니다. 잔고 캡처 등 내 정보를 보내지 마세요.
