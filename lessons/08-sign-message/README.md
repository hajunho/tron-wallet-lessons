## 🔍 원리 들여다보기 <a id="why"></a>

### 비유 → 정식 용어

| 비유 | 정식 용어 | 이 레슨에서 보는 값 |
|---|---|---|
| 그냥 종이에 도장 | 메시지 서명 `signMessageV2` | `0x` + 130 hex (65바이트) |
| 도장 무늬로 주인 찾기 | 서명에서 주소 복원 `verifyMessageV2` | 복원된 T주소 |
| "이건 편지가 아니에요" 표시 | 프리픽스 `\x19TRON Signed Message:\n` | 해시 앞에 붙는 고정 문자열 |
| 칸이 나뉜 종이 | 구조화 서명 TIP-712 `signTypedData` | domain + types + value |
| 어느 나라 종이인지 | domain의 `chainId` | Nile 3448148188 |

### 실험 1: 출력에서 한 줄 찾기

`npm run l08`을 실행하고 `[2]` 단계에서 다음 두 줄을 찾습니다.

```
  복원된 주소: TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH
  바꾼 메시지로 복원된 주소: TB18AarnHDJa9v7jvrVo1vzCgwztzyCP34
```

같은 서명인데 메시지 끝 글자 하나(`요` → `!`)만 바꿨더니 완전히 다른 주소가 나옵니다. 프로그램은 "틀렸다"고 말하지 않았습니다. 그냥 다른 주소를 돌려줬습니다. 그래서 검증은 항상 "복원된 주소 == 내가 기대한 주소" 비교입니다.

### 실험 2: 환경변수 바꿔 보기

```bash
MESSAGE="Hello Tron" npm run l08
CHAIN_ID=1029 npm run l08
```

첫 줄을 실행하면 `[3]`의 "이더리움 프리픽스로 복원한 주소"가 `TYnN1mkBeU44TWy3UZ71kDZ5USpRK4jAV1`로 바뀝니다. 같은 열쇠, 같은 메시지인데 프리픽스가 다르면 다른 주소가 나옵니다. 둘째 줄은 옆 나라 BTTC Donau의 chainId(1029)로 같은 Permit에 서명합니다(서명만 하고 아무것도 보내지 않습니다). `[4]`의 서명 값이 달라집니다. 서명 안에 나라 번호가 묶여 있다는 뜻입니다.

### 숫자로 확인하기

- 메시지 "나는 토리예요"는 글자 7개지만 UTF-8 바이트는 **19**개입니다(한글 6글자 × 3바이트 + 공백 1바이트). 프리픽스 뒤에 붙는 길이는 글자 수가 아니라 바이트 수입니다.
- 서명은 항상 65바이트 = 130 hex. 메시지가 길어도 서명 길이는 같습니다. 서명하는 대상이 메시지 자체가 아니라 메시지의 해시(32바이트)이기 때문입니다.

### 왜 그렇게 설계했을까?

왜 메시지 앞에 굳이 프리픽스를 붙일까요? 프리픽스가 없다면, 누군가 "이 메시지에 서명해 줘"라며 내민 바이트가 사실은 트랜잭션의 raw_data일 수 있습니다. 그러면 메시지 서명이 그대로 유효한 트랜잭션 서명이 됩니다. 프리픽스는 "이 서명은 절대 트랜잭션이 아니다"를 해시 단계에서 못 박는 장치입니다.

### 비유의 한계 (한 줄)

종이 도장은 우표가 안 들지만, 그 종이 한 장(예: Permit)으로 허락(권한)이 넘어갈 수 있습니다. 공짜라고 안전한 것이 아닙니다.

## 💻 코드로 확인하기 <a id="code"></a>

```bash
npm run l08
# 환경변수: MNEMONIC(없으면 데모), MESSAGE(기본 "나는 토리예요"), CHAIN_ID(기본 3448148188), SHOW_SECRETS, LEVEL
```

네트워크 호출이 없습니다. 실행 시간 1초 미만. 아래는 핵심 줄만 인용했고, 전체 출력은 [expected-output.txt](./expected-output.txt)를 봅니다.

**[1/6] 지갑 준비** — `walletFromMnemonic(mnemonic, 0)`으로 키를 만듭니다. `createTronWeb()`은 fullHost가 설정되지만 노드에 아무것도 묻지 않습니다.

```
  내 주소(T): TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH
  같은 키의 0x 주소: 0xC8599111F29c1e1E061265b4AF93eA1F274aD78A
```

**[2/6] signMessageV2 / verifyMessageV2** — `verifyMessageV2`는 "참/거짓"이 아니라 주소를 돌려줍니다. `if (await verifyMessageV2(...))`처럼 truthy 검사만 하면 형식만 맞는 서명이면 모두 통과합니다. 검증은 `recovered === me.address` 비교로 끝냅니다.

```
  복원된 주소: TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH
  내 주소와 비교: MATCH
  바꾼 메시지로 복원된 주소: TB18AarnHDJa9v7jvrVo1vzCgwztzyCP34
  내 주소와 비교: MISMATCH
```

**[3/6] 프리픽스 직접 계산** — tronweb 없이 ethers만으로 같은 해시를 만들고 검증할 수 있습니다(서버 검증 코드를 ethers로 짜도 된다는 뜻).

```js
const { utils: tronUtils } = require('tronweb'); // TronWeb.utils 는 undefined, 반드시 이렇게
const digest = ethers.keccak256(ethers.concat([
  ethers.toUtf8Bytes(tronUtils.message.TRON_MESSAGE_PREFIX),
  ethers.toUtf8Bytes(String(bytes.length)), bytes,
]));
const tron = TronWeb.address.fromHex('41' + ethers.recoverAddress(digest, signature).slice(2));
```

```
  tronweb hashMessage 와 비교: MATCH
  ethers.recoverAddress → T주소: TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH (MATCH)
  이더리움 프리픽스로 복원한 주소: TDHKsNC2AdETZKk2TrRaEMzbZL9zogLZha (MISMATCH)
```

**[4/6] signTypedData / verifyTypedData (TIP-712)** — domain은 `{ name, version, chainId, verifyingContract }`, types는 EIP-712와 같은 형식입니다.

```
  verifyTypedData(같은 domain): true
  verifyTypedData(chainId 바꿈) → 예외: Signature does not match
```

**[5/6] TIP-712 == EIP-712** — T주소를 0x주소로 바꾸기만 하면 `ethers.TypedDataEncoder.hash`가 같은 해시를 만들고, 그 해시로 복원한 주소가 서명자와 일치합니다.

```
  그 해시 + tronweb 서명으로 복원한 주소: TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH (MATCH)
```

**[6/6] 이 서명이 하는 일** — `verifyingContract`(어느 사탕통), `chainId`(어느 나라), `spender`(누구에게), `value`(얼마까지), `deadline`(언제까지) 다섯 칸을 표로 찍습니다. 이 Permit은 레슨용 예시 구조이며, Nile USDT 컨트랙트가 permit 함수를 실제로 지원하는지는 확인하지 않았습니다(확인 필요). 레슨 9에서 같은 의미의 `approve` 트랜잭션을 직접 봅니다.

### 트론 vs EVM 차이

| 항목 | 트론 | EVM(BTTC 등) |
|---|---|---|
| 메시지 프리픽스 | `\x19TRON Signed Message:\n` | `\x19Ethereum Signed Message:\n` |
| 구조화 서명 | TIP-712 (`signTypedData`) | EIP-712 — 해시 계산이 **동일** |
| 주소 표기 | T… (base58check, hex는 `41`+40hex) | 0x + 40hex |
| 검증 반환 | `verifyMessageV2` → 주소 / `verifyTypedData` → true 또는 **예외** | ethers `recoverAddress`·`verifyMessage`·`verifyTypedData` → 모두 주소 (ethers 6.17에서 확인됨) |
| 수수료 | 0 (대역폭·에너지 소모 없음) | 0 (gas 없음) |

### 함정 1개

`verifyTypedData`는 실패할 때 `false`를 돌려주지 않고 `Signature does not match` 예외를 던집니다. 반대로 `verifyMessageV2`는 실패해도 예외 없이 엉뚱한 주소를 돌려줍니다. 두 함수의 실패 신호가 정반대이므로, 둘 다 "try/catch + 주소 비교"로 감싸는 것이 안전합니다.

### 도전

- 쉬움: `MESSAGE`를 빈 문자열 `""`로 실행해 보세요. 바이트 길이 0이어도 서명이 만들어지는지, `[2]`의 "바꾼 메시지"가 무엇이 되는지 확인하세요.
- 어려움: Permit 서명 `typedSig`를 r(32바이트), s(32바이트), v(1바이트)로 직접 잘라 출력한 뒤 `ethers.recoverAddress(evmHash, { r, s, v })`로 복원해 같은 주소가 나오는지 확인하세요. (ethers 6.17에서 `{ r, s, v }` 객체 형식 동작 확인 — 서명자의 0x 주소가 나옵니다.)

## 🏠 내 생활에서는 <a id="life"></a>

지갑 앱(TronLink 등)에서 어떤 사이트에 접속하면 "서명 요청" 팝업이 뜹니다. 트랜잭션 확인 화면과 달리 금액·수수료 칸이 없고, "메시지"나 표 형태의 내용이 보입니다. 이것이 이 레슨의 메시지 서명과 구조화 서명입니다. 수수료가 0이라고 표시되더라도, 내용을 읽고 나서 승인하세요.

이 개념이 화면에서 보이는 자리(앱과 버전에 따라 문구는 다를 수 있습니다):

- 팝업 제목이 "전송"이나 "승인"이 아니라 "서명"·"메시지 서명"으로 적힌 화면. 금액 칸이 없다면 이 레슨의 메시지 서명입니다.
- 팝업 안에 이름과 값이 줄줄이 적힌 표가 보이는 화면. 구조화 서명(TIP-712)이며, 표의 각 줄이 이 레슨 `[6]` 단계의 다섯 칸에 해당합니다.
- 어느 네트워크에 연결되어 있는지 적힌 줄. 연습 나라(Nile)와 진짜 나라(메인넷)를 글자까지 확인하세요.

| 이런 요청이 오면 | 사기인가? | 이유 |
|---|---|---|
| 로그인 화면에서 "이 사이트에 로그인합니다"라는 짧은 문장과 내 주소, 날짜가 보이는 서명 요청 | 아니오(읽고 승인) | 내용이 읽히고, 누구에게 무엇을 허락하는 칸이 없습니다 |
| "에어드랍 확인용 무료 서명"이라며 긴 hex 숫자만 보이는 서명 요청 | 예 | 무엇에 서명하는지 읽을 수 없습니다. 규칙 8 |
| spender에 모르는 주소, value에 아주 큰 숫자, deadline이 먼 미래인 표가 보이는 서명 요청 | 예 | 내 토큰을 꺼내 갈 허락증입니다. 필요한 곳에 필요한 만큼만 |

**사기 유형 1개: "무료 서명" 피싱.** "가스비 없이 서명만 하면 됩니다"라며 서명 요청을 띄웁니다. 돈이 안 나가니 안전하다고 느끼지만, 그 서명이 허락증(레슨 9의 approve와 같은 의미)이면 나중에 토큰이 빠져나갑니다. 읽을 수 없으면 거절하세요.

**오늘 실천 습관 1개:** 서명 팝업이 뜨면 승인 전에 "누구에게(spender), 얼마(value), 언제까지(deadline)" 세 칸을 소리 내어 읽으세요. 세 칸이 없거나 읽을 수 없으면 닫으세요.

## 🛡️ 안전 규칙 카드 <a id="card"></a>

**규칙 8. 무엇에 도장 찍는지 읽지 못하면 찍지 않는다.**

**해야 할 것**
- ✅ 서명 요청의 내용을 끝까지 읽는다. (누구에게, 얼마, 언제까지, 어느 나라)
- ✅ "검증됨" 표시 대신, 복원된 주소가 내 주소와 같은지 본다.
- ✅ 수수료 0 서명도 트랜잭션처럼 신중하게 다룬다.

**절대 하지 말 것**
- ❌ 읽을 수 없는 hex만 보이는 서명 요청에 승인하지 않는다.
- ❌ "무료니까", "확인용이니까"라는 말만 듣고 찍지 않는다.
- ❌ 모르는 사이트에서 뜬 서명 팝업을 급하게 누르지 않는다.

## ✅ 확인하기 <a id="check"></a>

- **초등:** 여우 씨가 아무것도 안 적힌 종이에 도장을 찍어 달래요. 토리는 어떻게 해야 할까요? ① 친구니까 찍어 줘요 ② 뭐라고 쓸 건지 먼저 보여 달라고 해요 ③ 반만 찍어 줘요
- **중고등:** `verifyMessageV2`에 다른 메시지를 넣으면 예외 대신 다른 주소가 나옵니다. 그래서 검증 코드는 어떤 비교를 꼭 해야 하는지 이유와 함께 쓰세요.
- **개발자:** `verifyTypedData({ ...domain, chainId: 1029 }, types, value, typedSig, me.address)`를 `try { console.log('결과', r) } catch (e) { console.log('예외', e.message) }`로 감싸 실행하면 콘솔에 무엇이 찍힐까요?
