## 정답과 해설

### 🧒 초등
1. **②** — 허락증은 "꺼내 가도 됨"이지 "지금 줌"이 아니에요. 사탕은 친구가 실제로 꺼내 갈 때 줄어요.
2. **②** — 숫자 칸이 비면 "전부"예요. 3알이면 3알이라고 적고 나서 찍어요.
3. **②** — 빈 칸 허락증은 사탕통 전부를 꺼내 갈 수 있는 허락증이에요. 그래서 컴퓨터(guard)도 막아요.
4. **②** — 허락증을 돌려받아도 장부의 숫자는 그대로예요. 0으로 다시 적어야 끝나요.
5. **②** — 받는 데는 허락증이 필요 없어요. 허락증은 "내 것을 꺼내 가도 됨"이니까, 받으려고 찍으라는 말은 속임수예요.

### 🔍 중고등
1. 토큰이 나가는 순간은 spender가 `transferFrom(owner, to, value)`를 실행할 때입니다. 그 함수는 "owner가 spender에게 value 이상을 허락했는가"를 allowance에서 확인하고 통과해야만 잔고를 옮기므로, allowance가 없으면 아무리 spender라도 꺼내 갈 수 없습니다.
2. allowance는 spender가 꺼내 갈 수 있는 상한입니다. 3 USDT를 허락하면 최악의 경우에도 3 USDT만 잃지만, 2^256-1(사실상 무한)을 허락하면 상한이 내 잔고 전체가 되어 spender(또는 spender 컨트랙트의 구멍을 찾은 사람)가 전부를 가져갈 수 있습니다. 상한 = 위험의 크기입니다.
3. 22688 × 100 sun = 2,268,800 sun = 2.2688 TRX. 허락증(approve)도 컨트랙트 호출이라 에너지가 들고, 에너지가 없으면 TRX를 태워 대신합니다. USDT만 있고 TRX가 0이면 승인조차 못 하므로 규칙 4(연료가 먼저)와 같은 이야기입니다.
4. 종이 허락증은 돌려받으면 효력이 끝나지만, allowance는 컨트랙트 안의 숫자라서 spender가 다 쓰지 않는 한 저절로 줄지 않습니다. 끝내려면 `approve(spender, 0)` 트랜잭션을 한 번 더 보내야 하며, 여기에도 에너지가 듭니다.
5. `2dc6c0` = 2×16^5 + 13×16^4 + 12×16^3 + 6×16^2 + 12×16 + 0 = 2,097,152 + 851,968 + 49,152 + 1,536 + 192 + 0 = 3,000,000. decimals 6이므로 3,000,000 ÷ 10^6 = **3 USDT**.

### 💻 개발자
1. 1 USDT = 1,000,000 = 16진수 `f4240` → 64글자 끝 6글자는 `0f4240`. `[5]`의 판정은 `통과 (필요한 만큼만)` (1,000,000은 UNLIMITED/2보다 훨씬 작음).
2. `0x095ea7b3 true`. TRC-20의 approve 선택자는 ERC-20과 동일합니다(함수 시그니처가 같으므로 keccak256 앞 4바이트도 같음).
3. **다른 관문(SEND_TX)의 메시지**입니다. guard는 관문을 순서대로 검사하므로 SEND_TX=false에서는 첫 관문에서 `SEND_TX=false (기본값) 이므로 무제한 approve을(를) 보내지 않습니다. …`로 멈춥니다. 무제한 관문 메시지(`무제한(또는 사실상 무제한) approve 는 이 저장소에서 막습니다. …`)는 SEND_TX=true + 연습용 니모닉 + 테스트넷일 때 나옵니다. 그래서 스크립트는 같은 기준(`≥ UNLIMITED / 2`)을 로컬에서도 계산해 보여 줍니다.
4. 만드는 순간에는 예외가 나지 않지만, 돌아온 객체에 `approve` 메서드가 없습니다(`typeof c.approve` → `undefined`, 실행으로 확인). 그래서 `c.approve(...)`를 부르는 순간 "함수가 아니다"류의 TypeError가 납니다. `tronWeb.contract`는 JSON ABI 객체 배열만 이해하므로 `lib/tron.js`의 `TRC20_ABI`처럼 `{ name, type, inputs, outputs, stateMutability }` 객체 배열을 넘겨야 합니다. 조용히 실패하는 함정이라 더 위험합니다.
5. 트론 `data`는 ethers `calldata`에서 `0x`만 뗀 것과 바이트 단위로 같습니다. 출력 줄: `ethers calldata 와 비교: MATCH (트론 data = EVM calldata)`. `fee_limit`은 `30000000` sun(= 30 TRX), 이 트랜잭션이 태울 수 있는 에너지 비용의 상한입니다.

### 🏠 일반인
1. **아니오.** 받는 데는 승인이 필요 없습니다. 승인은 "내 토큰을 꺼내 가도 됨"이고, 무제한이면 지갑의 USDT 전부가 대상입니다. 닫으세요.
2. 금액을 **오늘 쓸 100 USDT로 직접 고쳐서** 승인하세요(앱의 "사용자 지정/이번 금액" 선택, 화면 구성은 앱마다 다름 — 확인 필요). 무제한이 편해 보여도 상한이 곧 위험의 크기입니다. 거래가 끝나면 남은 승인을 0으로 돌려놓으세요.
3. `095ea7b3`은 승인(approve), 끝의 `ffff…`는 무제한입니다. 누구에게 주는 승인인지 spender 주소를 읽을 수 없다면 거절하세요. 읽을 수 없으면 찍지 않습니다(규칙 8)와 필요한 만큼만(규칙 9)이 동시에 적용됩니다.
4. **그냥 두면 안 됩니다.** 토큰이 아직 내 지갑에 있어도, 그 서비스(또는 그 서비스에 구멍이 생기면 다른 사람)가 언제든 500 USDT까지 꺼내 갈 수 있습니다. 같은 spender에게 0을 승인해 취소하세요. 탐색기(Tronscan)의 승인 관리 기능으로도 확인·취소할 수 있다고 알려져 있으나 화면은 직접 확인하세요(확인 필요).
5. **틀립니다.** 승인도 컨트랙트 호출이라 수수료(TRX 소각 또는 에너지)가 들고, 승인한 금액만큼 나중에 토큰이 빠져나갈 수 있습니다. 돈이 나가는 순간이 뒤로 미뤄졌을 뿐입니다.
