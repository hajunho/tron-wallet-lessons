## 🧒 이야기로 시작 <a id="story"></a>

토리가 연습 나라 우체통 앞에 섰어요.

"넣으면 3초 뒤 새 장에 적혀."
톡, 봉투가 우체통에 들어갔어요.

토리가 소리쳐요. "어, 사탕 수를 잘못 썼어요!"

"붙은 장은 나도 못 떼. 지우개가 없어."

**엄마 아빠에게 물어보기:** "한 번 말하면 되돌릴 수 없는 말에는 어떤 게 있나요?"

## 🔍 원리 들여다보기 <a id="why"></a>

### 비유는 이렇게 바뀝니다

| 비유 | 정식 용어 | 스크립트에서 보이는 자리 |
|---|---|---|
| 우체통에 넣기 | 브로드캐스트 (`sendRawTransaction`) | `[5] 우체통에 넣기` |
| 봉투 번호 | txID (raw_data 의 sha256) | `[3] txID` |
| 유효기간 | expiration (기본 60초) | `[3] 유효기간 60초` |
| 우편함 새로 달기 | 계정 활성화 (1 TRX) | `[2] 활성화` |
| 종이 입장권 | 무료 대역폭 (하루 600 bytes) | `[1] 무료 대역폭` |
| 영수증 | receipt (`getTransactionInfo`) | `[6] 영수증 기다리기` |
| 우체통 앞에서 멈추기 | guard (`assertCanSend`) | `[4] 관문 통과 확인` |

### 실험 1 — 출력에서 한 줄 찾기

스크립트를 실행하고 `[3]` 블록에서 `유효기간` 줄을 찾으세요. `60초`가 보입니다. 도장을 찍고 60초가 지나면 노드가 봉투를 받지 않습니다. 그래서 스크립트는 서명 직후 곧바로 관문 단계로 갑니다. 왜 "오늘 서명해 두고 내일 보내기"가 안 되는지 숫자 하나로 확인됩니다.

### 실험 2 — 환경변수 바꿔 보기

```bash
AMOUNT_TRX=0.5 npm run l06
```

`[3]` 블록의 `금액` 줄이 `0.5 TRX (500000 sun)` 로 바뀝니다. 그런데 `[1]` 블록의 `필요 최대` 값도 같이 줄어듭니다.

| 금액 | 활성화비 | 대역폭 소각 | 필요 최대 |
|---|---|---|---|
| 1 TRX | 1 TRX | 0.266 TRX | 2.266 TRX |
| 0.5 TRX | 1 TRX | 0.266 TRX | 1.766 TRX |
| 0.001 TRX | 1 TRX | 0.266 TRX | 1.267 TRX |

금액이 얼마든 활성화비 1 TRX 와 대역폭 266 bytes × 1000 sun 은 똑같이 듭니다. 그래서 필요 최대는 1 TRX 아래로 내려가지 않습니다. "사탕 1알을 보내도 우표는 똑같이 든다"는 뜻입니다.

### 왜 그렇게 설계했을까?

트론은 왜 "보낸 것을 취소하는 기능"을 만들지 않았을까요? 장부지기(노드)가 여럿이고 모두가 같은 장부를 들고 있습니다. 한 명이 취소해 주면 그 노드의 장부만 다른 장부와 달라집니다. "아무도 혼자 고칠 수 없다"는 성질이 곧 "아무도 취소해 줄 수 없다"는 뜻입니다. 되돌릴 수 없다는 것은 결함이 아니라 설계입니다. 대신 트론은 취소 기능 자리에 `expiration`(60초)을 두었습니다. 보내기 전이라면 기다리기만 해도 봉투가 저절로 무효가 됩니다.

**비유의 한계 1줄:** 진짜 우체통은 편지를 꺼낼 수 있지만, 브로드캐스트는 노드가 `result: true` 를 돌려준 순간부터 회수할 방법이 없습니다.

## 💻 코드로 확인하기 <a id="code"></a>

### 실행

```bash
npm run l06                      # 미리보기(기본). [4]에서 멈추고 아무것도 보내지 않는다
AMOUNT_TRX=0.5 npm run l06       # 금액 바꾸기
TO=T... npm run l06              # 받는 주소 바꾸기 (기본은 같은 니모닉의 index 1)
```

실제 전송(`SEND_TX=true`)은 **이 저장소의 어느 경로에서도 하지 않습니다.** 모든 레슨은 미리보기(`SEND_TX=false`)로만 실행합니다. 관문이 무엇을 막는지는 `lib/guard.js` 의 `assertCanSend` 를 읽어 확인하세요.

- `MNEMONIC` 이 없으면 안내 후 `exit 1`. 데모 자동 대체는 없습니다. 재현 명령은 `expected-output.txt` 첫 줄.
- 실패 분기(주소 오류, 미활성화, 잔고 부족, 조회 실패, 노드 거부)는 모두 `exit 1`. guard 가 막은 미리보기만 `exit 0`.
- 기본 수신자가 index 1 인 이유: `to === from` 이면 `Cannot transfer TRX to the same account` 예외.

### 단계별 출력 해설

전체 출력은 `expected-output.txt` 에 있습니다. 각 단계가 무엇을 호출하고 무엇을 읽는지입니다.

| 단계 | 호출 | 읽는 값 |
|---|---|---|
| `[1]` 내 계정 | `getAccount` · `getBalance` · `getAccountResources` | `{}` 면 미활성화 / 잔고(sun) / `freeNetLimit` 600 |
| `[2]` 받는 사람 | `getAccount(to)` | `{}` 면 활성화비 1 TRX 추가 |
| `[3]` 빌드·서명 | `sendTrx` → `trx.sign` | expiration 60초, raw_data 133 bytes, 서명 65 bytes |
| `[4]` 관문 | `assertCanSend` | `GuardError` → 미리보기 종료, exit 0 |
| `[5]` 브로드캐스트 | `sendRawTransaction` | `{ result: true, txid }` 또는 `{ code, message(hex) }` |
| `[6]` 영수증 | `getTransactionInfo` (3초 간격, 최대 30초) | 처음엔 `{}`, 뒤에 `blockNumber`·`receipt` |

핵심 줄 발췌 (`[1]` 과 `[3]`):

```
  무료 대역폭: 600 / 600 bytes 남음 (오늘 사용 0)
  ✅ 보낼 수 있습니다 (잔고 55167.40829 TRX ≥ 필요 최대 2.266 TRX)
  │ 유효기간    60초 (expiration 2026-09-12T07:53:00.000Z)
  │ raw_data    133 bytes
  │ 서명        1개, 65 bytes
  txID 변화: 서명 전후 같음 (txID 는 raw_data 의 sha256)
```

"필요 최대"는 금액 + 활성화 1 TRX + 대역폭 0.266 TRX 입니다. 수신자가 활성화되어 있고 무료 대역폭이 남으면 실제로는 1 TRX 만 나갑니다.

```js
const needSun = amountSun + ACTIVATION_FEE_SUN + EST_TX_BYTES * BANDWIDTH_PRICE_SUN;
```

`ref_block_bytes`/`ref_block_hash`/`txID` 와 expiration 시각은 실행마다 달라집니다. `60초`·`133 bytes`·`65 bytes` 는 같아야 합니다. 체인에서 차감되는 크기는 봉투(protobuf) 포함 약 266 bytes 이고, 정확한 값은 receipt 로만 압니다.

`[4]` 가 멈추는 모습 — `script.js` 는 `GuardError` 만 잡아 안내 후 `return` 합니다(다른 예외는 다시 던짐).

```
  ⚠️  SEND_TX=false (기본값) 이므로 TRX 전송을(를) 보내지 않습니다. 실제로 보내려면 SEND_TX=true 를 앞에 붙이세요.
🛑 미리보기 종료 — 아무것도 보내지 않았습니다. 장부에는 아무 흔적도 남지 않습니다.
```

`[5]`·`[6]` 은 실행하지 않아 실제 출력이 없습니다. 거부 예: `code: 'CONTRACT_VALIDATE_ERROR'`, message 를 hex 에서 풀면 `Contract validate error : account [T...] does not exist`. 성공하면 `.last-tx.json` 의 txid 를 레슨 7이 읽습니다.

### 트론 vs EVM 차이

| | 트론 (Nile) | EVM (BTTC Donau 등) |
|---|---|---|
| 중복·순서 방지 | `ref_block_bytes/hash` + `expiration`(60초). nonce 없음 | `nonce` (계정별 순번) |
| 브로드캐스트 응답 | `{ result: true, txid }` 또는 `{ code, message(hex) }` | ethers `wallet.sendTransaction({ to, value, gasPrice })` → TransactionResponse 객체(`.hash`), 실패는 예외 (확인 필요) |
| 취소·가속 | 없음. 만료를 기다리거나 새로 빌드 | 같은 nonce 로 덮어쓰기 시도 가능(확인 필요) |
| 전송 수수료 | 대역폭 bytes(무료 600/일), 부족하면 1000 sun/byte | gas × gasPrice (Donau 21000 gas ≈ 189 BTT) |
| 영수증 | `getTransactionInfo` 가 몇 블록 뒤 채워짐 | `wait()` 로 receipt (확인 필요, 레슨 11) |

### 함정 1개

서명해 둔 트랜잭션을 "나중에" 보내면 안 됩니다. `expiration` 이 생성 후 60초라 그 뒤엔 실패합니다. 미리 서명해 두려면 서명 **전에** `extendExpiration(tx, 초)` 를 부르고 **반환된 객체만** 써야 합니다(원본의 `txID` 는 갱신되지 않아 서명하면 `Invalid transaction`).

### 도전

- (쉬움) `[1]` 에서 `freeNetLeft < 266` 이면 경고가 나옵니다. 무료 대역폭을 다 쓴 날 어떤 줄이 바뀌는지 예측하고 `expected-output.txt` 와 비교하세요.
- (어려움) `.last-tx.json` 에 `expiration`·`ref_block_bytes` 도 저장하고, 레슨 7이 "이 txid 는 어느 블록을 참조했는가"를 출력하게 이어 보세요(`lib/` 수정 금지).

## 🏠 내 생활에서는 <a id="life"></a>

- 지갑 앱(TronLink 등)의 "보내기" 화면에서 받는 주소·금액·네트워크를 입력하고 "확인"을 누르는 순간이 이 레슨의 `[5]` 입니다(화면·버튼 이름은 앱 버전마다 다를 수 있음, 확인 필요). 그 뒤로는 앱도, 고객센터도, 노드도 되돌려 주지 못합니다.
- 확인 화면이 바로 `[3]` 의 미리보기 표입니다. 주소 전체, 금액, 네트워크 이름, 수수료 네 칸을 손가락으로 한 줄씩 짚으며 읽고 누르세요. 주소는 앞 네 글자만 보지 말고 끝 네 글자까지 대조합니다.
- 거래소 출금 화면에서는 대개 "주소·네트워크(TRON(TRC20) 등, 표기는 거래소마다 다름, 확인 필요)·수수료" 세 칸이 보입니다. 네트워크 칸을 상대와 글자까지 맞춘 뒤, **처음 보내는 주소라면 소액을 먼저** 보내고 도착을 확인한 다음 나머지를 보내세요.
- 보낸 뒤에는 앱의 "완료" 표시 대신 txid 를 받아 두세요. 탐색기(`nile.tronscan.org` 같은)에서 그 txid 로 찾으면 장부가 무엇이라 적었는지 직접 볼 수 있습니다.

**이런 요청이 오면 사기인가?**

| 상황 | 사기? | 이유 |
|---|---|---|
| "잘못 보내셨네요. 열쇠(12단어)를 알려 주시면 되돌려 드릴게요"라는 연락 | 예 | 되돌리기는 불가능하고, 12단어를 묻는 순간 사기입니다 |
| "먼저 소액 보내서 확인해 보세요"라고 상대가 제안 | 아니오 | 규칙 6 그대로입니다. 다만 주소는 상대가 직접 보낸 것을 전체 대조하세요 |
| "지금 안 보내면 취소돼요, 빨리 확인 누르세요"라고 재촉 | 예 | 서두르게 만드는 것이 목적입니다. 봉투를 끝까지 읽을 시간을 뺏는 사람은 여우 씨입니다 |

**사기 유형 1개 — "되돌려 주기" 사기:** 잘못 보낸 사람을 찾아가 "우리가 회수해 드린다"며 열쇠나 수수료를 요구합니다. 장부는 아무도 되돌릴 수 없으므로, 회수를 약속하는 사람은 예외 없이 사기입니다.

**오늘 실천 습관 1개:** 지난 거래 하나의 txid 를 탐색기에서 열어 결과 칸(성공/실패)과 수수료 칸을 읽어 보세요. 오늘 무언가를 보낼 필요는 없습니다.

> 다음에 정말 보낼 일이 생기면: 처음 보내는 주소에는 먼저 소액을 보내고, 상대가 "받았다"가 아니라 **txid 로 도착을 확인**한 뒤 나머지를 보내세요(규칙 6). 이 코스 안에서는 아무것도 보내지 않고 화면만 봅니다.

## 🛡️ 안전 규칙 카드 <a id="card"></a>

**규칙 6. 보내면 되돌릴 수 없다. 처음 보내는 곳은 소액 먼저.**

**해야 할 것**
- ✅ 처음 보내는 주소에는 소액을 먼저 보내고, 도착을 확인한 뒤 나머지를 보낸다.
- ✅ 확인 화면(봉투)의 주소·금액·네트워크·수수료를 끝까지 읽고 누른다. 주소는 끝 네 글자까지 대조한다.
- ✅ 보낸 뒤 txid 를 적어 두고 탐색기에서 결과를 직접 확인한다.

**절대 하지 말 것**
- ❌ "되돌려 드린다"는 사람에게 열쇠(12단어)나 수수료를 주지 않는다. 회수는 누구도 못 한다.
- ❌ 재촉당하는 상태에서 "확인"을 누르지 않는다. 급할수록 한 번 멈추고 봉투를 다시 읽는다.
- ❌ 연습 나라에서 충분히 익히기 전에 진짜 나라(메인넷)에서 시도하지 않는다.
