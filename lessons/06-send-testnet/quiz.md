# Lesson 06 퀴즈 — 진짜로 보내기(연습 나라에서)

## 🧒 초등 — 그림·상황 고르기

**문제 1.** 토리가 봉투를 우체통에 넣었어요. 3초 뒤 장부에 적혔어요. 그런데 사탕 수를 잘못 썼대요. 어떻게 되나요?
① 노드 아저씨가 우체통에서 꺼내 줘요
② 장부를 지우개로 지워요
③ 되돌릴 수 없어요. 받은 친구가 새 봉투를 써 줘야 해요

**문제 2.** 처음 사탕을 보내는 친구가 있어요. 사탕 100알을 보내려고 해요. 토리는 어떻게 하나요?
① 100알을 한 번에 보내요
② 1알을 먼저 보내고, 장부에 잘 적혔는지 본 다음 나머지를 보내요
③ 친구가 먼저 보내 줄 때까지 기다려요

**문제 3.** 여우 씨가 말해요. "토리야, 잘못 보낸 거 내가 꺼내 줄게. 12단어 주문만 알려 줘." 토리는?
① 주문을 알려 줘요. 꺼내 준다니까요
② 안 알려 줘요. 아무도 꺼낼 수 없으니까 꺼내 준다는 말은 속임수예요
③ 주문 절반만 알려 줘요

**문제 4.** 다음 중 "우체통에 넣기"와 가장 비슷한 것은?
① 친구에게 편지를 쓰고 서랍에 넣어 두기
② 큰 소리로 교실 전체에 말하기 (모두가 들어서 안 한 척 못 함)
③ 일기장에 적었다가 지우기

**문제 5.** 연습 나라에서 사탕을 잘못 보냈어요. 왜 다행일까요?
① 연습 나라 사탕은 진짜 사탕이 아니라서요
② 연습 나라에서는 되돌릴 수 있어서요
③ 연습 나라 장부는 지워져서요

## 정답과 해설

### 🧒 초등
1. **③** — 장부지기가 여럿이라 한 명이 꺼내거나 지울 수 없어요. 되돌리는 방법은 받은 친구가 새 봉투를 써서 다시 보내는 것뿐이에요.
2. **②** — 1알이 잘 가면 이름을 제대로 쓴 거예요. 그다음에 나머지를 보내요.
3. **②** — 아무도 꺼낼 수 없어요. "꺼내 줄게"라는 말 자체가 속임수이고, 12단어는 노드 아저씨도 안 물어봐요.
4. **②** — 모두가 들었으니(장부지기 모두가 적었으니) 안 한 척 할 수 없어요. 서랍이나 일기장은 혼자 꺼내고 지울 수 있어서 달라요.
5. **①** — 연습 나라도 되돌릴 수 없고 장부도 안 지워져요. 다만 사탕이 진짜가 아니라서 실수를 연습으로 배울 수 있어요.

### 🔍 중고등
1. 노드(장부지기)는 여럿이고 모두 같은 장부를 갖고 있습니다. 한 노드가 취소해 주면 그 노드의 장부만 달라져 "아무도 혼자 고칠 수 없다"는 성질이 깨지므로, 취소 기능은 애초에 설계에 없습니다.
2. ① 보낼 금액, ② 수신자가 새 계정일 때의 활성화비 1 TRX(1,000,000 sun), ③ 무료 대역폭이 없을 때의 대역폭 소각 약 0.266 TRX(266 bytes × 1000 sun). 금액이 작아져도 ②③은 그대로라 1 TRX 아래로 내려가지 않습니다.
3. `[3]` 의 `유효기간 60초` 줄. expiration 이 생성 후 60초라 10분 뒤에는 만료되어 노드가 받지 않습니다. 미리 서명해 두려면 서명 전에 `extendExpiration` 을 써야 합니다.
4. 대역폭은 트랜잭션 **바이트 수**로 소모됩니다. 1 TRX 를 보내든 0.001 TRX 를 보내든 트랜잭션 크기는 약 266 bytes 로 같습니다. 하루 무료 600 bytes 안이면 0 TRX, 넘으면 266 × 1000 sun = 0.266 TRX 가 똑같이 듭니다.
5. 소액 전송은 "주소를 제대로 썼는가"를 실제 장부로 검증하는 것이지, 잘못 보낸 것을 되돌리는 것이 아닙니다. 100 TRX 를 보내려 할 때 1 TRX 를 먼저 보내면, 주소가 틀렸을 때 잃는 것이 100 이 아니라 1 로 **줄어듭니다**. 1 TRX 자체는 여전히 되돌릴 수 없습니다.

### 💻 개발자
1. `loadMnemonic()` 이 예외를 던지고, 스크립트가 "MNEMONIC 이 없습니다 …" 안내와 `cp .env.example .env` → `npm run new-wallet` → faucet 순서를 출력한 뒤 **exit 1** 로 끝납니다. 이 레슨은 데모 니모닉으로 자동 대체하지 않습니다.
2. 출력되지 않습니다. `[4]` 에서 `assertCanSend` 가 `GuardError` 를 던지고, 스크립트가 이를 잡아 "🛑 미리보기 종료"를 출력한 뒤 `return` 합니다. `process.exitCode` 를 건드리지 않으므로 **exit 0** 입니다.
3. `SEND_TX=true` 검사는 통과하지만 다음 검사에서 데모 니모닉이 걸립니다: `데모 니모닉(abandon … about)으로는 전송할 수 없습니다. npm run new-wallet 로 만든 연습용 니모닉을 .env 에 넣으세요.` 역시 `GuardError` 라 "미리보기 종료"로 exit 0 입니다. (설령 통과해도 데모 주소는 권한 키가 바뀌어 있어 노드가 거부합니다.)
4. `result.result === true` 가 아니므로 "❌ 노드가 거부했습니다." 다음에 `code: CONTRACT_VALIDATE_ERROR` 와 `message` 를 출력하고 `process.exitCode = 1` 로 끝납니다. message 는 hex 문자열이라 `decodeNodeMessage(result)` (내부적으로 `Buffer.from(message, 'hex').toString('utf8')`) 로 풀면 `Contract validate error : account [T...] does not exist` 가 됩니다.
5. 실패가 아닙니다. 방금 접수된 tx 는 아직 블록에 들어가지 않아(솔리디티 전) `getTransactionInfo` 가 빈 객체 `{}` 를 돌려줄 수 있습니다. 스크립트는 3초 간격으로 최대 30초 동안 `blockNumber` 가 생길 때까지 폴링하고, 그래도 없으면 "레슨 7에서 같은 txid 로 다시 확인"하라고 안내합니다.

### 🏠 일반인
1. **②** — 규칙 6 그대로입니다. ①은 상대의 말에 의존하고, ③은 앞 4글자만 같은 "닮은 주소" 사기에 당할 수 있습니다.
2. 끊으세요. 되돌리기는 누구도 할 수 없고, 12단어를 묻는 순간 사기입니다. 고객센터는 복구 구문을 묻지 않습니다.
3. 전화를 끊고 확인 화면의 주소·금액·네트워크를 끝까지 읽으세요. 서두르게 만드는 것이 목적입니다. 정말 필요한 전송이라면 나중에 다시 해도 됩니다(취소되면 새로 만들면 됩니다).
4. 충분하지 않습니다. 캡처는 누구나 만들 수 있습니다. txid 를 요구하고 탐색기에서 직접 결과와 금액을 확인하세요(레슨 7).
5. 취소되지 않을 가능성이 큽니다. 앱이 이미 노드에 브로드캐스트했다면 앱을 꺼도 장부에 적힙니다. "확인"을 누르기 전이 마지막 기회입니다.
